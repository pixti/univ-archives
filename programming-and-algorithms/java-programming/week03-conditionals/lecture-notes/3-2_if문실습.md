## 1. [실습] 좌표값의 분면 결정하기

```java
import java.util.Scanner;

public class Quadrant {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.println("좌표의 x값 >> ");
        int x = sc.nextInt();
        System.out.println("좌표의 y값 >> ");
        int y = sc.nextInt();
        sc.close();

        int qud;
        if (x == 0 || y == 0) {
            System.out.println("x나 y 중 하나가 0이면 분면 판단 불가");
            return;                         // main 메소드를 바로 끝낸다 (프로그램 종료)
        }
        if (x > 0) {
            if (y > 0) qud = 1;
            else qud = 4;
        }
        else {
            if (y > 0) qud = 2;
            else qud = 3;
        }
        System.out.println("좌표 (" + x + ", " + y + ")의 분면은 "
                           + qud + "분면입니다.");
    }
}
```

```
좌표의 x값 >>
4
좌표의 y값 >>
-3
좌표 (4, -3)의 분면은 4분면입니다.
```

> - `return;`은 **메소드를 즉시 끝낸다**. main에서 쓰면 프로그램이 그 자리에서 종료된다. 잘못된 입력을 걸러낼 때 자주 쓰는 패턴이다.
> - 💡 2주차 과제([`Quadrant.java`](../../week02-basics/assignment/expressions/Quadrant.java))는 `?:`만으로 풀어서 축 위의 점(0)을 처리하지 못했다. 이제 if 문으로 따로 걸러낼 수 있다.
> - ⚠ 슬라이드 코드는 `"...판단 불가“);`로 닫는 따옴표가 둥근 따옴표(`“`)라 컴파일 에러가 난다. 곧은 따옴표로 고쳤다.

### 다른 방법: 복합 조건식

분면을 검사하는 코드를 아래처럼 바꿀 수도 있다. **이해하기는 더 쉽다.**

```java
if (x > 0 && y > 0) qud = 1;
else if (x > 0 && y < 0) qud = 4;
else if (x < 0 && y > 0) qud = 2;
else qud = 3;
```

하지만 **최악의 경우(3분면)에는 이전 코드보다 비교를 더 많이 한다.**

| 방식 | 3분면 (x<0, y<0)일 때 비교 횟수 |
|---|---|
| 중첩 if | `x > 0` 1번 + `y > 0` 1번 = **2번** |
| else if + `&&` | `x > 0`(1번째, 단축 평가) + `x > 0`(2번째, 단축 평가) + `x < 0`, `y > 0`(3번째) = **4번** |

## 2. [실습] 메뉴 방식의 사칙 연산

```java
import java.util.Scanner;

public class Calculator {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.println("첫 번째 숫자 (음수도 가능) >> ");
        int a = sc.nextInt();
        System.out.println("두 번째 숫자 (음수도 가능) >> ");
        int b = sc.nextInt();
        System.out.println("연산 (a : 덧셈, s : 뺄셈, m : 곱셈, d : 나눗셈)을 선택하세요.");
        /* Scanner 클래스는 한 글자를 읽어 들이는 메소드가 제공되지 않기 때문에
           next() 메소드로 문자열을 읽은 후
           charAt() 메소드를 이용하여 첫 번째 문자 가져옴 */
        char c = sc.next().charAt(0);
        sc.close();

        double result;
        if (c == 'a') result = a + b;
        else if (c == 's') result = a - b;
        else if (c == 'm') result = a * b;
        else if (c == 'd') result = a / b;
        else {
            System.out.println("허용되지 않는 문자입니다.");
            return;
        }
        System.out.println("결과는 " + result + "입니다.");
    }
}
```

```
첫 번째 숫자 (음수도 가능) >>
3
두 번째 숫자 (음수도 가능) >>
5
연산 (a : 덧셈, s : 뺄셈, m : 곱셈, d : 나눗셈)을 선택하세요.
m
결과는 15.0입니다.
```

> 참고: **`sc.next().charAt(0)`**
> - `sc.next()`는 공백 전까지의 단어 하나를 **String**으로 읽는다.
> - `.charAt(0)`은 그 문자열의 **0번째(첫 번째) 글자**를 char로 꺼낸다. 인덱스는 0부터 시작한다.
> - `"add"`를 입력해도 `'a'`만 쓰인다.
>
> 💡 **주의할 점 2가지**
> 1. `result`가 double이지만 `a / b`는 **int끼리의 나눗셈**이다. 그래서 `7 / 2`는 먼저 `3`이 되고, 그다음 `3.0`으로 저장된다. 소수점까지 보려면 `(double) a / b`로 써야 한다(2주차 형변환 참고).
> 2. `b`가 0인데 `d`를 고르면 `ArithmeticException: / by zero`로 프로그램이 죽는다. 실습 문제 풀이([`SimpleCalculator.java`](../practice/conditionals1/SimpleCalculator.java))에서는 `if (y != 0)`으로 막았다.
>
> - `result`는 선언만 하고 초기화하지 않았다. 그래도 컴파일 에러가 나지 않는다. else 블록이 `return;`으로 끝나므로, 출력문에 도달하는 **모든 경로에서 result에 값이 대입**되기 때문이다. 자바 컴파일러는 이를 확인하는데, 이것을 "확정 대입(definite assignment)"이라고 한다.

→ [`examples/Calculator.java`](../examples/Calculator.java), switch 버전은 [3-3](3-3_if문실습_switch문.md) 참고

## 3. [실습] 문자 변환 (대문자 ↔ 소문자)

```java
import java.util.Scanner;

public class CaseConversion {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.println("영문자를 입력하세요 : ");
        char c = sc.next().charAt(0);
        sc.close();

        if (c >= 'a' && c <= 'z') c = (char)(c - 'a' + 'A');
        else if (c >= 'A' && c <= 'Z') c = (char)(c - 'A' + 'a');
        else {
            System.out.println("영문자가 아닙니다.");
            return;
        }
        System.out.println("변환 결과 : " + c);
    }
}
```

```
영문자를 입력하세요 :
B
변환 결과 : b
```

- 문자는 내부적으로 **2Byte 숫자(유니코드)**로 표현된다.
- 그래서 **코드값을 비교해서** 대문자인지 소문자인지 판별할 수 있다(`c >= 'a' && c <= 'z'`).

> 📝 **필기 (실습 · 조건문1 3번):**
> - 아스키코드상 `A`는 65, ..., `Z`는 90, `[`는 91, ...이다. `a`는 97, ..., `z`는 122이다.
> - char 타입은 내부적으로 아스키 코드(int) 값으로 저장된다. 따라서 두 문자를 빼면 알파벳 순서상 떨어져 있는 **"거리(알파벳 위치 차이)"**를 구할 수 있다.
> - 문자들 간의 거리는 어떻게 구할까? `x = 'B'`라고 하자. `x - 'A'`는 실제로는 `66 - 65`라서 1이 나온다.
>   - `'B' - 'A'` → `66 - 65` = **1** (A로부터 1번째 뒤에 위치)
>   - `'Z' - 'A'` → `90 - 65` = **25** (A로부터 25번째 뒤에 위치)
> - 대문자를 소문자로 바꾸는 식은 `'a' + (x - 'A')`이다.
>   1. `x - 'A'` → `'B' - 'A'` = **1** (거리 계산)
>   2. `'a' + 1` → `97 + 1` = **98**
>   3. `(char) 98` → **`'b'`**
>
> 💡 `char - char`, `char + int`의 결과는 **int**다(2주차: 연산 시 int로 자동 형변환). 그래서 다시 char 변수에 넣으려면 `(char)`로 **강제 형변환**해야 한다.
> 💡 대문자와 소문자는 항상 **32**만큼 차이 난다(`'a' - 'A'` = 97 − 65 = 32). 그래서 `c + 32`로 써도 되지만, `'a' - 'A'`처럼 의미가 드러나게 쓰는 편이 읽기 좋다.
