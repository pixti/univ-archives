## 1. 생성자

- 생성자: 클래스로부터 **객체가 생성되면서 자동으로 호출되는 메소드**
- 주로 객체의 데이터(필드)를 **초기화**하는 데 쓴다.
- **클래스 이름과 같은 이름**을 쓰며 **반환형이 없다**.
- 보통 `public` 접근자를 쓰지만 `private`와 `protected` 접근자도 가능하다.
  - `private`이면 같은 클래스 안에서만 생성할 수 있다.
  - `protected`는 추상 클래스에서 주로 쓴다.

```java
public class ConstructorExample {
    public static void main(String[] args) {
        Cat c = new Cat("이쁜이", 45);
        System.out.println(c.toString() + "의 몸무게는 " + c.getSize());
    }
}

class Cat {
    int size;
    String name;
    public Cat(String n, int s) {
        name = n;
        size = s;
    }
    public int getSize() { return size; }
    public String toString() { return name; }
}
```

```
이쁜이의 몸무게는 45
```

> 참고:
> - 📝 **필기 (퀴즈):** 객체가 생성될 때 → 생성자. 객체가 소멸될 때 → 소멸자. 자바에서는 (소멸 시점을) **가비지 컬렉터가 결정**한다. → `finalize` (5절)
> - 💡 `new Cat("이쁜이", 45)`가 실행되는 순서
>   1. Heap에 `Cat` 객체를 만들고 필드를 기본값(`size = 0`, `name = null`)으로 채운다.
>   2. 인수 개수·자료형이 맞는 생성자 `Cat(String, int)`를 호출해 필드를 초기화한다.
>   3. 만들어진 객체의 레퍼런스를 `c`에 대입한다.
> - 💡 **생성자를 하나도 만들지 않으면** 컴파일러가 매개변수 없는 **기본 생성자** `Cat() {}`를 자동으로 넣어 준다. 7강까지 `new Book()`처럼 쓸 수 있었던 이유다.
>   하지만 위처럼 `Cat(String, int)`를 하나라도 만들면 기본 생성자는 **자동으로 생기지 않는다**. 이때 `new Cat()`은 컴파일 오류다.
>   ```
>   error: constructor Cat in class Cat cannot be applied to given types;
>     required: String,int
>     found:    no arguments
>   ```
> - 💡 생성자에 `void`를 붙이면 생성자가 아니라 **이름이 클래스와 같은 일반 메소드**가 된다. (퀴즈 1번의 `void Cat()`)
> - 💡 `toString()`을 만들어 두면 `c.toString()` 대신 `System.out.println(c)`나 `"" + c`만 써도 자동으로 호출된다. (7강 과제 📝 `@Override`)
> - 📝 **필기 (퀴즈, AI 설명) 생성자와 getter / setter의 차이:** 생성자는 객체가 **처음 만들어질 때 딱 한 번** 초기 상태를 세팅하고, getter / setter는 객체가 **만들어진 이후 필요할 때마다** 값을 안전하게 읽거나 바꾼다. 자세한 내용은 [`quiz/ConstructorQuiz.java`](../quiz/ConstructorQuiz.java)의 `q1Extra()`에 있다.

## 2. [실습] 학생 성적 클래스 정의하기 – 전체, 과목별 평균

- 7강(8-1, 8-2)에서 `setInfo(...)`로 값을 넣던 학생 성적 예제를 **생성자**로 바꾼 것이다.

```java
class StudentScore {
    String sname;
    int sid, kor, eng, math;
    public StudentScore(String name, int id, int k, int e, int m) {
        sname = name; sid = id; kor = k; eng = e; math = m;
    }
    double getAverage() {
        return (kor + eng + math) / 3.0;
    }
    String getInfo() {
        return sname + ", " + sid + ", " + kor + ", " + eng + ", " + math;
    }
}
```

```java
public class StudentScoreTest {
    public static void main(String[] args) {
        int korSum = 0, engSum = 0, mathSum = 0;
        double totalSum = 0.0, korAvg, engAvg, mathAvg, totalAvg;
        StudentScore[] students = new StudentScore[3];
        students[0] = new StudentScore("bmkim1", 2016001, 70, 80, 90);
        students[1] = new StudentScore("bmkim2", 2016002, 60, 70, 80);
        students[2] = new StudentScore("bmkim3", 2016003, 50, 60, 70);
        for (int i = 0; i < 3; i++) {
            System.out.println(students[i].getInfo());
            korSum += students[i].kor;
            engSum += students[i].eng;
            mathSum += students[i].math;
            totalSum += students[i].getAverage();
        }
        korAvg = korSum / 3.0;
        engAvg = engSum / 3.0;
        mathAvg = mathSum / 3.0;
        totalAvg = totalSum / 3.0;
        System.out.println("국어 평균 : " + korAvg);
        System.out.println("영어 평균 : " + engAvg);
        System.out.println("수학 평균 : " + mathAvg);
        System.out.println("전체 평균 : " + totalAvg);
    }
}
```

```
bmkim1, 2016001, 70, 80, 90
bmkim2, 2016002, 60, 70, 80
bmkim3, 2016003, 50, 60, 70
국어 평균 : 60.0
영어 평균 : 70.0
수학 평균 : 80.0
전체 평균 : 70.0
```

> 참고:
> - ⚠ 슬라이드 5의 `public StudentScoreTest {`에는 `class`가 빠져 있다. `public class StudentScoreTest {`가 맞다.
> - 💡 7강 방식과 비교
>   ```java
>   // 7강: 객체를 만든 뒤 메소드로 값을 넣음 (2단계)
>   students[0] = new Student();

>   생성자를 쓰면 "값이 비어 있는 객체"가 생기는 순간이 없고, `setInfo`를 깜빡 잊는 실수도 막을 수 있다.

## 3. 생성자 중복 정의 (오버로딩)

- 생성자도 **메소드 오버로딩 규칙에 맞게** 여러 개를 중복 정의할 수 있다.

```java
class Cat {
    int size;
    String name;
    public Cat() {
        name = "영순이";
        size = 50;
    }
    public Cat(String n, int s) {
        name = n;
        size = s;
    }
    public int getSize() { return size; }
    public String toString() { return name; }
}
```

> 참고:
> - 📝 **필기 (퀴즈) 오버로딩:** 메소드를 여러 형태로 제공해 주는 것. 파라미터의 개수나 타입이 다르게. **중복정의(overloading)** 라고 한다.
> - 📝 **필기 (퀴즈, AI 설명) 오버로딩 핵심 규칙:**
>   - 메소드 **이름**이 완전히 같아야 한다.
>   - 파라미터의 **개수, 타입(자료형), 순서** 중 하나 이상이 반드시 달라야 한다.
>   - 반환(return) 타입만 다르게 설정하는 것은 오버로딩으로 인정되지 않는다.
>   - **도입 장점:** 가장 대표적인 예가 `System.out.println()`이다. 오버로딩이 없다면 숫자, 문자, 문자열을 출력할 때마다 `printlnInt()`, `printlnString()`처럼 각기 다른 이름을 외워야 한다. 오버로딩 덕분에 `println()` 하나만 기억하고 값을 넘기면 컴파일러가 알맞은 메소드를 찾아 실행하므로 가독성과 편의성이 크게 좋아진다.
> - ⚠ 슬라이드 7, 11, 12의 `“영순이”`, `“r1 면적은 ”` 등은 스마트 따옴표(`“ ”`)라서 그대로 붙여 넣으면 컴파일 오류가 난다. 코드에서는 `"`로 고쳤다.

## 4. [실습] 생성자 중복

```java
class MyPoint {
    private int x, y;
    public MyPoint() { x = 0; y = 0; }
    public MyPoint(int a, int b) { x = a; y = b; }
    public int getX() { return x; }
    public void setX(int newX) { x = newX; }
    public int getY() { return y; }
    public void setY(int newY) { y = newY; }
}

class MyRectangle {
    private MyPoint corner;
    private int width, height;
    public MyRectangle() {                          // 생성자 중복 정의
        corner = new MyPoint(0, 0);
        width = 0; height = 0;
    }
    public MyRectangle(MyPoint p, int w, int h) {   // 생성자 중복 정의
        corner = p;
        width = w; height = h;
    }
    public MyRectangle(int x, int y, int w, int h) { // 생성자 중복 정의
        corner = new MyPoint(x, y);
        width = w; height = h;
    }
    public MyPoint getPoint() { return corner; }
    public void setPoint(MyPoint newP) { corner = newP; }
    public int getWidth() { return width; }
    public void setWidth(int newW) { width = newW; }
    public int getHeight() { return height; }
    public void setHeight(int newY) { height = newY; }
    public void resize(int newW, int newH) {
        width = newW; height = newH;
    }
    public int getArea() { return width * height; }
}

public class MyRectangleTest {
    public static void main(String[] args) {
        MyRectangle r1 = new MyRectangle();
        MyRectangle r2 = new MyRectangle(new MyPoint(3, 3), 5, 6);
        MyRectangle r3 = new MyRectangle(3, 3, 6, 6);
        System.out.println("r1 면적은 " + r1.getArea() + "입니다.");
        System.out.println("r2 면적은 " + r2.getArea() + "입니다.");
        System.out.println("r3 면적은 " + r3.getArea() + "입니다.");
    }
}
```

```
r1 면적은 0입니다.
r2 면적은 30입니다.
r3 면적은 36입니다.
```

> 참고:
> - 💡 7강 8-5의 `MyRectangle`은 `corner = new MyPoint()`를 필드 선언에서 했고 값은 setter로 넣었다. 여기서는 생성자 세 개 중 **어떤 것으로 만들어도** `corner`가 반드시 채워진다.
> - 💡 `r2`는 밖에서 만든 `MyPoint` 객체를 그대로 받고, `r3`는 좌표(정수)만 받아 생성자 안에서 `MyPoint`를 만든다. 사용하는 쪽이 편한 방법을 고를 수 있는 것이 생성자 오버로딩의 장점이다.

## 5. 생성자와 this 키워드

### 5-1. 생성자 안에서 다른 생성자 호출: `this(...)`

- 생성자 안에서 **다른 생성자를 호출**할 때 `this` 키워드를 쓴다. 이때 **첫 문장**에 나와야 한다.

```java
class Cat {
    int size;
    String name;
    public Cat() {
        //System.out.println("test"); 이 줄이 주석이 아니면 오류
        this("영순이", 50); // this 사용, 첫 줄이 아니면 오류
    }
    public Cat(String n, int s) {
        name = n; // this.name = n; 과 동일
        size = s; // this.size = s; 와 동일
    }
    public int getSize() { return size; }
    public String toString() { return name; }
}
```

> 참고:
> - 📝 **필기 (퀴즈 1번):** 다른 생성자를 호출할 때는 반드시 1번째 줄에 와야 한다.
> - 📝 **필기 (실습 1번):** 생성자 체이닝 `this()` 기법. 매개변수가 가장 많은 생성자 하나에만 실제 대입 코드를 두고, 나머지 생성자는 `this(...)`로 기본값을 채워 그 생성자를 호출한다.
>   ```java
>   public Plane()                { this(0, null, 0); }
>   public Plane(int id)          { this(id, null, 0); }
>   public Plane(int id, String model) { this(id, model, 0); }
>   public Plane(int id, String model, int passenger) {   // ← 실제 초기화는 여기서만
>       this.id = id; this.model = model; this.passenger = passenger;
>   }
>   ```
>   초기화 코드가 한 곳에 모이므로 중복이 없고, 고칠 때도 한 곳만 고치면 된다. 과제 4번의 `rectCount++`처럼 "객체가 만들어질 때마다 꼭 해야 하는 일"도 마지막 생성자 한 곳에만 쓰면 된다.
> - ⚠ **JDK 25부터 바뀐 점 (Flexible Constructor Bodies, JEP 513):** 슬라이드의 "첫 줄이 아니면 오류"는 **Java 24까지**의 규칙이다. 이 저장소에서 쓰는 **JDK 25**에서는 `this(...)` 앞에 `System.out.println("test");`처럼 **아직 만들어지지 않은 객체(`this`)를 건드리지 않는 문장**을 쓸 수 있다. 직접 컴파일해 보면 결과가 다르다.
>
>   | 컴파일 | `System.out.println("test"); this("영순이", 50);` |
>   |---|---|
>   | JDK 21 (`javac --release 21`) | ❌ `error: flexible constructors is not supported in -source 21` |
>   | JDK 25 | ✅ 정상 컴파일 (`test` 출력 후 `this(...)` 실행) |
>
>   단, `this(...)` 앞에서 `name = "x";`처럼 **필드에 값을 읽거나 쓰는 것**(`this` 사용)은 JDK 25에서도 오류다. 시험은 교재 기준이므로 "**`this()`는 생성자의 첫 문장**"으로 답한다.

### 5-2. 매개변수 이름과 필드 이름이 같을 때: `this.필드`

- 메소드 인수명과 필드명이 같을 경우, 컴파일러가 혼동하지 않도록 `this` 키워드를 쓴다.

```java
public Cat(String name, int size) {
    name = name;      // ❌ 매개변수 name에 자기 자신을 대입 → 필드는 그대로 null
    size = size;      // ❌ 필드는 그대로 0
}
```

```java
public Cat(String name, int size) {
    this.name = name; // this 키워드 사용
    this.size = size; // this 키워드 사용
}
```

> 참고:
> - 💡 첫 번째 코드도 **컴파일은 된다**. 그래서 더 위험하다. 메소드 안에서는 매개변수가 필드보다 우선하므로 `name = name;`은 매개변수 → 매개변수 대입이 되어 아무 일도 하지 않는다. 결과적으로 `new Cat("나비", 3)`을 해도 `name`은 `null`, `size`는 `0`으로 남는다. (7강 8-2 📝 `this`가 필요한 이유)
> - 💡 `this`의 두 가지 쓰임 정리
>
>   | 형태 | 의미 | 쓰는 곳 |
>   |---|---|---|
>   | `this.필드`, `this.메소드()` | 현재 객체의 필드·메소드 | 일반 메소드, 생성자 |
>   | `this(인수...)` | 같은 클래스의 **다른 생성자** 호출 | **생성자 안에서만** (첫 문장) |

## 6. 상수 필드 및 정적 필드 초기화

### 6-1. 상수 필드 초기화

- `final` 키워드를 멤버 변수 앞에 붙여 **상수 필드**를 선언한다.
- 상수 필드는 ① 선언과 함께 초기화하거나, ② **생성자에서** 초기화할 수 있다.

```java
class Cat {
    private final int MAX_SIZE = 100;   // ① 선언과 함께 초기화
    private String name;
    ...
}
```

```java
class Cat {
    private final int MAX_SIZE;         // ② 생성자에서 초기화
    private String name;
    ...
    public Cat() {
        MAX_SIZE = 100;
    }
}
```

> 참고:
> - 💡 `final` 필드는 **딱 한 번만** 값을 넣을 수 있다. 값을 넣은 뒤 다시 대입하면 `error: cannot assign a value to final variable MAX_SIZE`.
> - 💡 ②처럼 선언만 해 둔 `final` 필드(blank final)는 **모든 생성자**에서 반드시 값을 넣어야 한다. 하나라도 빠뜨리면 `error: variable MAX_SIZE might not have been initialized`.
> - 💡 ②의 장점: 객체마다 다른 상수 값을 줄 수 있다. 예를 들어 `public Cat(int max) { MAX_SIZE = max; }`로 만들면 고양이마다 최대 크기가 다르지만, 한 번 정해지면 바뀌지 않는다. 9-1의 `LocalDate`가 `private final int year;`를 이런 방식으로 쓴다.

### 6-2. 정적 필드 초기화

- 정적 필드는 선언과 함께 초기화할 수 있다.

```java
class Cat {
    private static int MAX_SIZE = 100;
    private String name;
    ...
}
```

- 정적 필드는 생성자에서 초기화할 수 없다. 대신 **정적 필드 초기화 문(static 블록)** 을 써서 초기화할 수 있다.

```java
class Cat {
    private static int MAX_SIZE;
    private String name;
    ...
    static { MAX_SIZE = 100; }
}
```

> 참고:
> - 💡 정적 필드는 객체가 아니라 **클래스가 처음 로드될 때 한 번** 만들어진다(7강 8-2). 생성자는 객체를 만들 때마다 실행되므로 정적 필드를 초기화하기에 맞지 않다. 그래서 클래스가 로드될 때 **한 번만 실행되는 `static { ... }` 블록**을 쓴다.
> - ⚠ "생성자에서 초기화할 수 없음"은 정확히 말하면 다음과 같다.
>   - `static final` 필드(정적 상수): 생성자에서 대입하면 **컴파일 오류**다.
>   - 그냥 `static` 필드: 생성자에서 대입하는 것 자체는 **문법상 가능**하다. 하지만 객체를 만들 때마다 값이 다시 덮어써지므로 "초기화"가 아니다. 객체를 하나도 만들지 않으면 아예 초기화되지 않는다.
>
>   퀴즈 1번의 `Cat() { this("영순이", 50); MAX_WEIGHT = 100; }`가 두 번째 경우다(`MAX_WEIGHT`는 `final`이 아니라 컴파일은 된다). 직접 확인하는 코드는 [`examples/FieldInitTest.java`](../examples/FieldInitTest.java)에 있다.
> - 💡 static 블록은 계산이 필요한 초기화에 유용하다. 예: `static int[] squares = new int[10]; static { for (int i = 0; i < 10; i++) squares[i] = i * i; }`

| 필드 종류 | 선언과 함께 초기화 | 생성자에서 초기화 | static 블록에서 초기화 |
|---|---|---|---|
| 일반 필드 | ✅ | ✅ | ❌ |
| `final` 필드 (상수) | ✅ | ✅ (한 번만) | ❌ |
| `static` 필드 | ✅ | △ (가능하지만 매번 덮어씀) | ✅ |
| `static final` 필드 | ✅ | ❌ 컴파일 오류 | ✅ |

## 7. 소멸자

- 소멸자: **객체가 소멸될 때 자동으로 호출되는 메소드**
- C++에서는 클래스 이름 앞에 `~`를 붙인 형태다. (예: `~Cat()`)
- Java에서는 이런 형태의 소멸자가 없지만 `finalize` 메소드를 제공한다. 필요하면 `finalize` 메소드를 정의한다.
- 자바에서 객체 소멸은 **객체 변수를 `null`로 지정**한다.
  - **가비지 컬렉터(GC)** 가 적당한 시점에 그 객체를 제거하고, 그 시점에 `finalize` 메소드를 호출한다.
- 가비지 컬렉터가 적당한 시점에 객체를 소멸하기 때문에 **객체의 소멸 시기를 정확히 알 수 없다**는 점에 주의한다.

```java
Test obj = new Test();
…
obj = null;
```

```java
public class ConstructorExample {
    public static void main(String[] args) throws Throwable {
        Cat c = new Cat("이쁜이", 45);
        Cat c2 = new Cat();
        System.out.println(c.toString() + "의 몸무게는 " + c.getSize());
        System.out.println(c2.toString() + "의 몸무게는 " + c2.getSize());
        // c = null;
        // c2 = null;
    }
}

class Cat {
    int size;
    String name;
    public Cat() {
        this("영순이", 50);
    }
    public Cat(String n, int s) {
        name = n;
        size = s;
    }
    public int getSize() { return size; }
    public String toString() {
        return name;
    }
    public void finalize() {
        System.out.println(name + " 고양이가 소멸됨");
    }
}
```

```
이쁜이의 몸무게는 45
영순이의 몸무게는 50
```

> 참고:
> - 📝 **필기 (퀴즈):** 객체가 소멸될 때 소멸자. 자바에서는 가비지 컬렉터가 결정함. → 파이널라이즈(`finalize`)
> - 💡 위 코드를 실행해도 "고양이가 소멸됨"은 **출력되지 않는다**. `c = null;` 주석을 풀어도 마찬가지다. 프로그램이 너무 빨리 끝나서 GC가 돌 기회가 없고, 프로그램 종료 시에는 `finalize`를 호출해 주지 않기 때문이다. 이것이 "소멸 시기를 정확히 알 수 없다"는 말의 뜻이다.
>   `System.gc();`로 GC를 **요청**하면 보통 호출되는 것을 볼 수 있지만 이것도 보장은 아니다. → [`examples/FinalizeTest.java`](../examples/FinalizeTest.java)
> - 💡 레퍼런스가 끊겨 **아무 변수도 가리키지 않는 객체**가 GC 대상이 된다. `null` 대입 외에도 다른 객체를 대입하거나(`c = new Cat();`) 지역 변수의 블록이 끝나는 경우에도 대상이 된다.
> - 💡 `throws Throwable`은 `Object`의 `finalize()`가 `throws Throwable`로 선언되어 있어서 붙인 것이다. 위 코드처럼 `finalize()`를 직접 호출하지 않으면 없어도 된다(예외 처리는 11강).
> - 💡 `Object`의 `finalize()`는 `protected`인데 여기서는 `public`으로 재정의했다. 재정의할 때 접근 범위를 **넓히는 것**은 허용된다(10강 상속).
> - ⚠ **`finalize()`는 Java 9부터 deprecated, Java 18부터 "삭제 예정(for removal)"** 이다(JEP 421). JDK 25로 컴파일하면 다음 경고가 나온다.
>   ```
>   warning: [removal] finalize() in Object has been deprecated and marked for removal
>   ```
>   호출 시점을 알 수 없고 성능 문제도 있기 때문이다. 실무에서는 파일·네트워크 같은 자원을 정리할 때 `close()` 메소드 + `try-with-resources`(`AutoCloseable`)를 쓴다(13강 파일 입출력). 수업에서는 "자바의 소멸자 = `finalize`"로 개념만 이해하면 된다.

| | C++ | Java |
|---|---|---|
| 소멸자 형태 | `~클래스명()` | `finalize()` (deprecated) |
| 소멸 시점 | `delete` 또는 블록 끝 → **즉시** | GC가 결정 → **알 수 없음** |
| 메모리 해제 | 개발자가 직접 | 가비지 컬렉터가 자동으로 |
