## 1. 필드 접근자

- 필드를 선언할 때 자료형 앞에 **아무것도 없으면**, 그 필드는 **같은 패키지 안에서 어디서든** 접근할 수 있다.
- 즉, 필드가 선언된 클래스뿐 아니라 **같은 패키지에 선언된 다른 클래스**에서도 접근할 수 있다.

```java
package bmkim.java; // 같은 패키지 , 두 클래스

public class FirstClass {
    int field1;
    public void method1() {… field1 = 3;}
    public void method2() {... System.out.println(field1); ... }
    public static void main(String[] args) {
        ...
    }
}

class SecondClass {
    ...
    public void method3() {
        FirstClass ob = new FirstClass();
        ...
        ob.field1 = 3; // 다른 클래스에서 직접 접근
        ...
    }
}
```

```java
package bmkim.test; // package bmkim.java와 다른 패키지
import bmkim.java.FirstClass;

public class ThirdClass {
    ...
    public void method4() {
        FirstClass ob = new FirstClass();
        ...
        ob.field1 = 5; // 접근 불가능
        ...
    }
}
```

- 필드의 자료형 앞에 **접근수정자**를 붙일 수 있다.
  - **public**: 다른 패키지에서도 접근할 수 있다.
  - **private**: 해당 클래스 **내부에서만** 접근할 수 있다.
  - **protected**: 상속 부분에서 추가로 설명한다.
- public으로 선언한 필드는 언제 어디서든 제약 없이 값을 바꿀 수 있다. 그래서 **유지보수에 문제**가 생길 염려가 있다.
- private 필드는 **public 메소드로 접근**한다.
  - **getter**: private으로 선언된 필드 값을 **읽는** 메소드
  - **setter**: private으로 선언된 필드 값을 **수정하는** 메소드

| 접근수정자 | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 클래스 | 다른 패키지 |
|---|---|---|---|---|
| `public` | ✅ | ✅ | ✅ | ✅ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| (생략, default) | ✅ | ✅ | ❌ | ❌ |
| `private` | ✅ | ❌ | ❌ | ❌ |

> 참고:
> - 📝 **필기 (퀴즈 2번, AI 설명) getter/setter를 쓰는 이유:** 객체지향의 **캡슐화(Encapsulation)**와 **정보 은닉(Data Hiding)** 때문이다.
>   1. **데이터 무결성 / 유효성 검사**: setter 안에 조건문을 넣어 잘못된 값(예: 음수 나이)이 들어가지 않게 막는다. (실습 클래스1 2번의 연봉 범위 검사)
>   2. **접근 권한 제어**: getter만 만들면 **읽기 전용**, setter만 만들면 **쓰기 전용**이 된다.
>   3. **유지보수성**: 클래스 내부 구조(필드 이름, 저장 방식)가 바뀌어도 외부에서 쓰는 메소드는 그대로 둘 수 있다.
> - 📝 **필기 (실습 클래스1 3번, AI 설명):** private은 **객체가 아닌 클래스 단위**로 접근을 제어한다. 그래서 같은 클래스 안에서는 다른 객체(`c`)의 private 필드에도 `c.real`처럼 직접 접근할 수 있다. `c.getReal()`을 거치지 않아도 된다.
> - 💡 표의 `protected`와 자식 클래스는 10주차(상속)에서 다룬다.
> - ⚠ 슬라이드의 FirstClass에는 `method1`이 두 번 정의되어 있다. 매개변수까지 똑같은 메소드를 두 번 정의하면 컴파일 오류가 난다. 위에서는 두 번째를 `method2`로 고쳤다. 또 `import`문은 `package`문 **뒤에** 와야 하는데, 슬라이드에는 순서가 거꾸로 되어 있어 바로잡았다.

## 2. [실습] 접근자에 따른 변수 접근성 확인하기

- main에서 `students[i].kor` 대신 getter인 `students[i].getKor()`로 읽는다.

```java
public class StudentScore {
    public static void main(String[] args) {
        ...
        for(int i=0; i < 3; i++) {
            System.out.println(students[i].getInfo());
            korSum += students[i].getKor();
            engSum += students[i].getEng();
            mathSum += students[i].getMath();
            totalSum += students[i].getAverage();
        }
        ...
    }
}

class Student {
    private String sname;
    private int sid, kor, eng, math;
    public String getName() {return sname;}
    public int getSID() {return sid;}
    public int getKor() {return kor;}
    public int getEng() {return eng;}
    public int getMath() {return math;}
    void setInfo(String name, int id, int k, int e, int m) {
        sname = name; sid = id; kor = k; eng = e; math = m;

    double getAverage() { return (kor + eng + math)/3.0;}
    String getInfo() {
        return sname + ", " + sid + ", " + kor + ", " + eng + ", " + math;
    }
}
```

>   ```

## 3. [실습] 사각형 클래스

```java
class MyRectangle {
    // 필드 정의, private로 선언하여 외부접근 불가.
    private int x, y;           // 왼쪽 코너 좌표
    private int width, height;  // 사각형의 폭과 높이
    // 메소드 정의
    public int getX() {return x;}                     // x값을 읽는 기능
    public void setX(int newX) {x = newX;}            // x값을 변경하는 기능
    public int getY() {return y;}                     // y값을 읽는 기능
    public void setY(int newY) {y = newY;}            // y값을 변경하는 기능
    public int getWidth() {return width;}             // width 값을 읽는 기능
    public void setWidth(int newW) {width = newW;}    // width 값을 변경하는 기능
    public int getHeight() {return height;}           // height 값을 읽는 기능
    public void setHeight(int newY) {height = newY;}  // height 값을 변경하는 기능
    public void resize(int newW, int newH)
        {width = newW; height = newH;}                // 크기를 변경하는 기능
    public int getArea() {return width *height;}      // 면적을 계산하는 기능
}

public class MyRectangleTest {
    public static void main(String[] args) {
        MyRectangle r1 = new MyRectangle();
        r1.setX(10); r1.setY(10); r1.setWidth(5); r1.setHeight(4);
        System.out.println("면적은 " + r1.getArea() + "입니다.");
    }
}
```

```
면적은 20입니다.
```

> 참고:
> - 💡 getter는 `get + 필드명`, setter는 `set + 필드명`으로 짓는다. 필드명의 첫 글자는 대문자로 쓴다. boolean 필드의 getter는 `is + 필드명`으로 짓는다. (과제 클래스2 2번 CellPhone의 `isPower()`, `isCamera()`)
> - ⚠ 슬라이드 main의 스마트 따옴표(`“ ”`)는 일반 따옴표로 바꿨다. `setHeight(int newY)`의 매개변수 이름은 `newH`가 자연스럽다. 동작은 같다.
> - 💡 8-5에서는 이 MyRectangle의 좌표(x, y)를 MyPoint 클래스로 묶는다.

## 4. 변수의 유효 범위

- 변수는 **클래스 안(필드)**에도, **메소드 안이나 블록 안(지역 변수)**에도 선언할 수 있다.
- **선언 위치에 따라** 접근할 수 있는 범위와 생존 기간이 달라진다.

```java
class Test {
    int x;                         // 필드 : f(), g() 모두 사용 가능
    void f() { x++; }
    void g() { System.out.println(x); }
}
```

```java
class Test {
    void f() {
        int x = 3;   // f()함수가 끝나면 사라짐
        x++;
    }
    void g() { System.out.println(x); }   // 오류 : g()에서는 x를 모른다
}
```

## 5. [실습] 변수의 유효범위 테스트

```java
public class VariableScopeTest {
    public static void main(String[] args) {
        VariableScope app = new VariableScope();
        app.method1();
        app.method2();
    }
}

class VariableScope {
    int x = 3;
    public void method1() {
        int y = 5;
        System.out.println("x = " + x + " y = " + y);
    }
    public void method2() {
        System.out.println("x = " + x + " y = " + y); // method1 지역변수 오류
        for(int z=0; z < 3; z++) System.out.println("z = " + z);
        System.out.println("z = " + z); // for 문의 z를 사용하여 오류
    }
}
```

```
error: cannot find symbol      ← y (method1의 지역 변수)
error: cannot find symbol      ← z (for 문의 변수)
```

```
class VariableScope {
    int x = 3; ─────────────────────────────┐  필드 : 클래스 전체
    method1() {                             │
        int y = 5; ──────┐ method1 안에서만  │
    } ───────────────────┘                  │
    method2() {                             │
        for (int z ...) { ──┐ for 안에서만   │
        } ──────────────────┘               │
    }                                       │
} ──────────────────────────────────────────┘
```

> 참고:
> - 💡 오류가 나는 두 줄을 고친 실행 가능한 버전은 [`examples/VariableScopeTest.java`](../examples/VariableScopeTest.java)에 있다.
> - 📝 **필기 (퀴즈 1번, AI 설명):** 지역 변수는 블록이 실행될 때 **Stack**에 생겼다가 블록을 벗어나면 사라진다. 자동 초기화되지 않으므로 사용하기 전에 꼭 값을 넣어야 한다. 필드는 기본값으로 자동 초기화된다.
> - 💡 for 문 밖에서도 z를 쓰려면 `int z;`를 for 문 **앞에** 선언하고 `for (z = 0; z < 3; z++)`로 쓴다. 반복이 끝난 뒤 z는 3이다.

## 6. 메소드 중복정의 (오버로딩, overloading)

- **같은 이름의 메소드로 여러 형태를 지원**하는 것이다.
- 예를 들어 `System.out.println`도 다양한 형태로 중복정의되어 있다. 그래서 자료형에 상관없이 같은 메소드로 불러 쓸 수 있다.

```java
int f1() {...}
int f1(int x) {...}          // ok
int f1(int x, int y) {...}   // ok
int f1(double x) {...}       // ok
void f1(int x)               // error , 두번째 함수와 구분하지 못함
```

> 참고:
> - 💡 메소드를 구분하는 기준은 **이름 + 매개변수의 개수·자료형·순서**다. 이것을 시그니처라고 한다. **반환형은 포함되지 않는다.** 그래서 `int f1(int x)`와 `void f1(int x)`는 같은 메소드로 보고 오류가 난다. 호출문 `f1(3);`만 보고는 어느 쪽인지 알 수 없기 때문이다.

## 7. [실습] 정수 클래스의 기능 중복 정의하기

```java
public class MyIntegerTest {
    public static void main(String[] args) {
        MyInteger ob = new MyInteger();
        int x = ob.add(5);
        double y = ob.add(3.5);
        System.out.println(x + ", " + y);
    }
}

class MyInteger {
    int val;
    int add(MyInteger ob) { return this.val + ob.val;}  // 중복정의
    int add(int i) {return this.val + i;}                // 중복정의
    double add(double d) {return this.val + d;}          // 중복정의
    int subtract(MyInteger ob) {return this.val - ob.val;}
    int multiply(MyInteger ob) {return this.val * ob.val;}
    double divide(MyInteger ob) { return ((double) this.val)/ob.val;}
}
```

```
5, 3.5
```

> 참고:
> - 💡 `val`은 필드라서 기본값 0으로 자동 초기화된다. 그래서 `ob.add(5)`는 `0 + 5 = 5`, `ob.add(3.5)`는 `0 + 3.5 = 3.5`다.
> - ⚠ 슬라이드의 `add(int i) {return this.val + I;}`는 대문자 `I`라서 컴파일 오류가 난다(`cannot find symbol`). 위 코드는 `i`로 고쳤다.
