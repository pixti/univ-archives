## 1. 상속 및 접근 제어

### 상속이란

- **상속**은 부모 클래스에 정의된 필드와 메소드를 물려받는 것이다.
- 상속받은 클래스의 일부 기능을 **재정의**해서 쓸 수 있다.
- 상속을 통해 **소프트웨어 재사용성**이 높아진다.

| 구분 | 부르는 이름 |
|---|---|
| 기능을 물려주는 클래스 | 부모, 상위, 슈퍼 클래스 |
| 기능을 받는 클래스 | 자식, 하위, 파생 클래스 |

- `extends` 키워드로 부모 클래스를 지정한다.

```java
class Subclass extends Superclass { … }
```

- 접근자에 따라 하위 클래스에서 쓸 수 있는 부모 클래스의 기능이 제한된다.

### 상속의 구조 예: SportsCar

부모 클래스 `Car`를 상속한 `SportsCar`는 다음과 같은 구조다(UML에서 `+`는 public, `-`는 private).

```
         SportsCar
┌──────────────────────┐
│ +speed               │
│ +gear                │
│ +color               │   ← 부모 클래스 Car에서 상속받은 부분
│ +setGear()           │
│ +speedUp()           │
│ +speedDown()         │
├──────────────────────┤
│ -turbo : bool        │   ← 추가한 부분
│ +setTurbo()          │
└──────────────────────┘
```

- 자식 클래스에는 새로 필요한 `turbo`와 `setTurbo()`만 쓰면 된다. 나머지는 부모에게서 물려받는다.

> 💡 **보충:**
> - 자바에는 `bool`이 없다. 코드로 옮길 때는 `boolean`을 쓴다. → [`examples/SportsCarTest.java`](../examples/SportsCarTest.java)
> - 자식 객체는 부모의 필드와 자기 필드를 **모두** 가진다. 하지만 부모 객체(`new Car()`)에는 `turbo`가 없다.
> - 자바는 클래스를 **하나만** `extends`할 수 있다(단일 상속). 여러 부모의 기능이 필요하면 인터페이스를 쓴다(10-2).

### 접근자에 따른 접근 범위

| | `private` | `default` | `protected` | `public` |
|---|:-:|:-:|:-:|:-:|
| 동일 클래스 | O | O | O | O |
| 동일 패키지 하위 클래스 | | O | O | O |
| 동일 패키지 비하위 클래스 | | O | O | O |
| 다른 패키지 내 하위 클래스 | | | O | O |
| 다른 패키지 내 비하위 클래스 | | | | O |

> 💡 **보충:**
> - `default`는 접근자를 **아무것도 쓰지 않은** 경우다. package-private이라고도 한다.
> - 같은 패키지 안에서는 `default`와 `protected`의 차이가 없다. 차이는 **다른 패키지의 하위 클래스**에서 생긴다.
>   즉 `protected` = `default`(같은 패키지) + 다른 패키지의 하위 클래스.
> - 📝 **필기 (퀴즈 1번 (5)):** 어떤 필드가 package private으로 선언되었다면, 그 필드가 선언된 **자기 자신의 클래스**와 **같은 패키지(같은 디렉터리)** 안의 클래스에서만 직접 접근할 수 있다.
>   - 같은 패키지 내부: 상속 여부와 상관없이 어떤 클래스에서든 직접 접근할 수 있다.
>   - 다른 패키지 외부: 절대 직접 접근할 수 없다. 해당 클래스를 상속받은 자식 클래스라도 다른 패키지에 있으면 접근할 수 없다. (다른 패키지의 자식 클래스까지 허용하려면 `protected`를 쓴다)

### (1) 동일 클래스 내 접근 원칙

접근자의 종류와 무관하게 모든 필드 및 메소드에 접근할 수 있다.

```java
class A {
    private int a = 1;
    int b = 5;
    protected int c = 10;
    public int d = 15;
    void test() {
        System.out.println(a);
        System.out.println(b);
        System.out.println(c);
        System.out.println(d);
    }
}
```

### (2) 동일 패키지 내 하위 클래스의 접근 원칙

`private` 필드나 메소드를 제외한 나머지에 접근할 수 있다.

```java
class A {
    private int a = 1;
    int b = 5;
    protected int c = 10;
    public int d = 15;
}
class B extends A {
    void test() {
        System.out.println(a); // 접근 오류
        System.out.println(b);
        System.out.println(c);
        System.out.println(d);
    }
}
```

```
error: a has private access in A
```

> ⚠ **자주 틀리는 부분:** `private` 필드도 **물려받기는 한다.** `B` 객체 안에는 `a`가 들어 있다. 다만 `B`의 코드에서 `a`라는 이름으로 직접 쓸 수 없을 뿐이다. 부모의 public 메소드(getter 등)를 거치면 쓸 수 있다.
> 📝 **필기 (퀴즈 2번 (2)):** 상속을 받게 되면 부모 클래스 private 데이터도 물려받는데 임의로 건드릴 수 없음. 공개된 메서드를 사용하든지, 부모 생성자에서 호출하는 방향으로 초기화해야 한다.

### (3) 동일 패키지 내 비하위 클래스의 접근 원칙

하위 클래스와 똑같이 `private` 필드나 메소드를 제외한 나머지에 접근할 수 있다.

```java
class A {
    private int a = 1;
    int b = 5;
    protected int c = 10;
    public int d = 15;
}
class B {
    void test() {
        A ob = new A();
        System.out.println(ob.a); // 접근 오류
        System.out.println(ob.b);
        System.out.println(ob.c);
        System.out.println(ob.d);
    }
}
```

→ (1)~(3)을 한 파일로 실행: [`examples/AccessControlTest.java`](../examples/AccessControlTest.java) ((3)의 비하위 클래스는 (2)와 이름이 겹쳐서 `C`로 바꿨다)

```

---- (2) 하위 클래스 B 안에서 ----

a 는 getA() 로 : 1
---- (3) 비하위 클래스 C 안에서 ----

```

### (4) 다른 패키지 내의 하위 클래스의 접근 원칙

`protected`와 `public`만 접근할 수 있다.

```java
package otherpkg;      // 부모 클래스 A가 있는 다른 패키지 (패키지 이름은 예시)
public class A {
    private int a = 1;
    int b = 5;
    protected int c = 10;
    public int d = 15;
}
```

```java
import otherpkg.A;
class B extends A {
    void test() {
        System.out.println(a); // 접근 오류
        System.out.println(b); // 접근 오류
        System.out.println(c);
        System.out.println(d);
    }
}
```

### (5) 다른 패키지 내의 비하위 클래스의 접근 원칙

`public`만 접근할 수 있다.

```java
class B {
    void test() {
        A ob = new A();
        System.out.println(ob.a); // 접근 오류
        System.out.println(ob.b); // 접근 오류
        System.out.println(ob.c); // 접근 오류
        System.out.println(ob.d);
    }
}
```

→ [`examples/OtherPackageAccessTest.java`](../examples/OtherPackageAccessTest.java) (부모 `A`는 [`examples/otherpkg/A.java`](../examples/otherpkg/A.java))

```
---- (4) 다른 패키지의 하위 클래스 ----
10
15
---- (5) 다른 패키지의 비하위 클래스 ----
15
```

> 💡 **보충:**
> - 다른 패키지에서 쓰려면 **클래스 자체도 `public`**이어야 한다. `public`이 없는 클래스는 다른 패키지에서 import할 수 없다.
> - 컴파일 오류 메시지
>   ```
>   error: a has private access in A
>   error: b is not public in A; cannot be accessed from outside package
>   error: c has protected access in A
>   ```
> - ⚠ **자주 틀리는 부분:** 다른 패키지의 하위 클래스라도 `A ob = new A(); ob.c`처럼 **부모 타입 객체를 새로 만들어서** protected 멤버에 접근할 수는 없다. 자기 자신이 물려받은 `c`로만 접근할 수 있다.

## 2. 메소드 재정의 (method overriding)

- 상위 클래스의 메소드를 **똑같은 형태**로 다시 정의하는 것이다. (이름이 동일하고, 인수의 개수와 타입도 동일)

```java
class A {
    ...
    void f1() {...}
    void f1(int x) {...}
}
class B extends A {
    ...
    // A의 f1() 도 사용 가능
    void f1(int x) {...}        // A의 인수 한 개 f1을 재정의
    void f1(int x, int y) {...} // B에 새로 추가된 인수 두 개 f1
}
```

- 재정의되는 메소드에서 기존 메소드를 사용할 경우 **재귀에 빠질 위험**이 있으니 주의한다.
- 다음과 같은 형태로 새로운 재정의 메소드에서 기존 메소드를 호출한다.

```java
class B extends A {
    ...
    void f1(int x) { f1(5); ...}       // 재귀 호출로 인한 무한 반복
    void f1(int x, int y) {...}
}
```

```java
class B extends A {
    ...
    void f1(int x) { super.f1(5); ...} // 올바른 기존 메소드 호출
    void f1(int x, int y) {...}
}
```

→ [`examples/MethodOverridingTest.java`](../examples/MethodOverridingTest.java)

```
---- B 객체 ----
A.f1()
B.f1(int) : x = 1
A.f1(int) : x = 5
B.f1(int, int) : x = 2, y = 3
---- A 타입 변수에 B 객체 ----
B.f1(int) : x = 7
A.f1(int) : x = 5
---- super 없이 f1(5) 를 부르면 ----
StackOverflowError : 자기 자신을 끝없이 호출했다
```

> 📝 **필기 (퀴즈 1번 (1)): 재정의된 부모 메서드 호출하기**
> - `super` 키워드를 써서 `super.메서드이름()` 형태로 호출한다.
> - 자식 클래스에서 부모 클래스의 메서드를 재정의(오버라이딩)하면 부모의 메서드는 가려진다(은닉). 그래서 자식 클래스 안에서 그냥 `메서드이름()`으로 호출하면 자식이 재정의한 메서드가 실행된다.
> - 가려진 부모의 원래 메서드를 호출하려면 부모 클래스의 참조값을 가지고 있는 예약어 `super`와 도트 연산자(`.`)를 써서 명시적으로 호출한다.
>   ```java
>   class Parent {
>       void display() { System.out.println("부모 메서드"); }
>   }
>   class Child extends Parent {
>       @Override
>       void display() {
>           super.display(); // 부모 클래스의 display() 호출
>           System.out.println("자식 메서드");
>       }
>   }
>   ```

> 📝 **필기 (퀴즈 1번 (2)): 중복 정의(overloading)와 재정의(overriding)의 차이**
> - **중복 정의:** 같은 클래스 안(또는 상속 관계)에서 메서드 이름은 같지만 **매개변수의 개수나 타입(시그니처)을 다르게** 하여 새 메서드를 여러 개 정의하는 것
> - **재정의:** **상속 관계**에서 부모 클래스에 정의된 메서드를 자식 클래스에서 **동일한 시그니처(이름, 매개변수, 반환형)**로 다시 작성(덮어쓰기)하는 것
>
> | 구분 | 중복 정의 (Overloading) | 재정의 (Overriding) |
> |---|---|---|
> | 관계 | 주로 같은 클래스 내부 (상속 관계도 가능) | 반드시 부모-자식 간의 상속 관계 |
> | 메서드 이름 | 동일함 | 동일함 |
> | 매개변수 (개수, 타입) | 반드시 달라야 함 | 반드시 같아야 함 |
> | 반환형 | 상관없음 | 같아야 함 (또는 하위 타입) |
> | 접근 지정자 | 상관없음 | 부모보다 좁은 범위로 변경 불가 |
> | 목적 | 같은 기능에 대해 다양한 입력을 처리 (편의성) | 부모의 기능을 자식의 특성에 맞게 변경 (다형성) |

> 📝 **필기 (퀴즈 1번 (3)):** 자식 클래스에 부모 클래스의 멤버 함수와 **시그니처가 같은** 멤버 함수가 있으면 → **재정의**다.
> - 메서드 시그니처(Method Signature)란 "메서드의 이름"과 "매개변수 리스트(개수, 데이터 타입, 순서)"를 뜻한다.
> - 시그니처(매개변수)가 달랐다면 중복 정의다. 그래서 위 `B`의 `f1(int x, int y)`는 상속 관계에서의 **중복 정의**다.

> 📝 **필기 (퀴즈 1번 (4)): 메서드 재정의는 어떤 용도로 쓰나?**
> 부모 클래스로부터 상속받은 기본 기능을 **자식 클래스의 상황과 특성에 맞게 변경(수정)하거나 확장**하기 위해 쓴다. 이를 통해 객체지향의 핵심인 **다형성(Polymorphism)**을 구현한다.
> 1. **특수화(Specialization):** 부모 클래스가 제공하는 일반적인 기능이 자식 클래스에 맞지 않을 때, 자식 클래스에 알맞은 동작으로 교체하기 위해 쓴다. (예: 동물 클래스의 `소리내기()`를 강아지 클래스에서는 "멍멍", 고양이 클래스에서는 "야옹"이 출력되도록 재정의)
> 2. **다형성 및 동적 바인딩 구현:** 부모 타입의 참조 변수로 여러 자식 객체를 다룰 때, 같은 메서드를 호출해도 실행 시점(Runtime)에 실제 자식 객체의 재정의된 메서드가 알아서 실행되게 만든다. 코드의 유지보수성과 확장성이 크게 좋아진다. (10-3)

> 💡 **보충:**
> - 메소드 위에 `@Override`를 붙이면 컴파일러가 "정말 부모에 같은 메소드가 있는지" 검사해 준다. `f1(int x)`를 `f1(long x)`처럼 잘못 쓰면 재정의가 아니라 새 메소드(중복 정의)가 되는데, `@Override`가 있으면 오류로 알려 준다.
>   ```
>   error: method does not override or implement a method from a supertype
>   ```
> - 재정의할 때 접근 범위를 좁힐 수 없다. 부모가 `public`이면 자식도 `public`이어야 한다.
> - ⚠ **자주 틀리는 부분:** 재정의한 메소드 안에서 `super.`를 빼고 같은 메소드를 부르면 **자기 자신을 다시 부르는 무한 재귀**가 되어 `StackOverflowError`로 끝난다. 퀴즈 3번 (9) `Student.print()`에서 `super.print()`를 쓰는 이유다.

## 3. final 메소드 상속

- `final` 키워드가 붙은 메소드는 하위 클래스에서 **재정의할 수 없다**.
- 클래스 앞에 `final` 키워드가 붙으면 **상속할 수 없다**.

```java
class Parent { final void show() {...} }
class Child extends Parent {
    void show() {...}          // ❌ 재정의 불가
}

final class Last {...}
class Next extends Last {...}  // ❌ 상속 불가
```

```
error: show() in Child cannot override show() in Parent
  overridden method is final
error: cannot inherit from final Last
```

→ [`examples/FinalMethodTest.java`](../examples/FinalMethodTest.java)

> 💡 **보충: `final`의 세 가지 쓰임**
>
> | 붙는 곳 | 의미 |
> |---|---|
> | 변수 | 값을 한 번만 정할 수 있다 (상수) |
> | 메소드 | 재정의할 수 없다 |
> | 클래스 | 상속할 수 없다. 예: `String`, `Integer`, `Math` |
>
> `final` 메소드도 물려받아서 **호출하는 것**은 된다. 바꿀 수만 없다.

## 4. 상위 클래스 생성자 호출 순서

- 자식 클래스는 부모 클래스로부터 상속받은 멤버들이 있다. 그것을 초기화하기 위해 **부모 클래스의 생성자도 자동으로 호출**된다.
- C++에서 소멸자는 역순으로 호출되지만, Java의 경우 가비지 컬렉터에 따라 달라질 수 있다.
- 자식 클래스에서 부모 클래스의 **특정 생성자**를 호출할 때는 `super` 키워드를 사용한다.
- 부모 생성자 호출은 코드 **제일 앞**에 위치시켜야 한다.

### 상속에서의 생성자와 소멸자 순서

자식 클래스의 객체가 생성될 때에 당연히 자식 클래스의 생성자는 호출된다. 이때에 부모 클래스 생성자도 호출될까? → **호출된다. 부모가 먼저다.**

```
객체의 생성   [부모 클래스 생성자] ──▶ [자식 클래스 생성자]
                                              │
객체의 사용                                   …
                                              │
객체의 소멸   [부모 클래스 소멸자] ◀── [자식 클래스 소멸자]
```

\* 위의 순서는 일반적인 얘기다. 소멸자의 실행 순서는 보장할 수 없다. 가비지 컬렉터에 따른다.

```java
public class Program {
    public static void main(String[] args) {
        Rectangle r;
        r = new Rectangle();
    }
}
class Shape {
    private int x, y;
    public Shape() {
        System.out.println("Shape 생성자");
    }
    public void finalize() {
        System.out.println("Shape 소멸자");
    }
}
class Rectangle extends Shape {
    private int width, height;
    public Rectangle() {
        System.out.println("Rectangle 생성자");
    }
    public void finalize() {
        System.out.println("Rectangle 소멸자");
    }
}
```

```
Shape 생성자
Rectangle 생성자
```

→ [`examples/ConstructorOrderTest.java`](../examples/ConstructorOrderTest.java) (GC를 요청해서 소멸자 출력까지 확인)

> ⚠ **자주 틀리는 부분:**
> - 강의 코드의 main은 `static void main(string args[])`이다. 자바의 문자열 클래스는 대문자 **`String`**이고, main에는 **`public`**이 있어야 시작점이 된다. (C#은 소문자 `string`을 쓴다) 위 코드는 `public static void main(String[] args)`로 고쳐서 실었다.
> - 자바의 `finalize()`는 C++ 소멸자와 달리 **부모 것이 자동으로 호출되지 않는다.** 위 `Rectangle`처럼 `finalize()`를 재정의하고 `super.finalize()`를 부르지 않으면 "Shape 소멸자"는 출력되지 않는다. 부모 쪽 정리도 하려면 마지막에 `super.finalize()`를 직접 호출해야 한다.
>   ```
>   ---- GC 요청 ----
>   Rectangle 소멸자          ← 강의 코드 : Shape 소멸자는 안 나옴
>   RectangleSuper 소멸자     ← super.finalize() 를 부른 버전
>   Shape 소멸자
>   ```
> - `finalize()`는 Java 9부터 deprecated, Java 18부터 삭제 예정(for removal)이다. 호출 시점도, 호출 여부도 보장되지 않는다. (9-3 소멸자)

> 📝 **필기 (퀴즈 2번):**
> - (1) "자식 생성자가 부모 생성자를 명시적으로 호출하지 않으면 부모 생성자는 호출되지 않는다" → **X**. 컴파일러가 자동으로 부모의 기본 생성자 `super()`를 (자식 생성자의 첫 줄에) 넣어 호출한다.
> - (3) "자식 생성자가 먼저 호출된 후 부모 생성자가 호출된다" → **X**. 부모가 호출이 되고 자식이 호출이 됨. 자식이 부모의 멤버를 쓰려면 부모 쪽 멤버가 먼저 초기화되어 있어야 하기 때문이다.
> - (4) "소멸자는 자식 → 부모 순서" → **O**. 객체가 소멸될 때는 생성자의 역순으로 진행된다. 부모가 먼저 소멸해 버리면 자식이 소멸하는 과정에서 부모의 자원을 참조할 때 문제가 생길 수 있기 때문이다.
>   📝 자바에서는 소멸자가 없는 형태로 가고 있어서 중복 정답 처리하겠다(고 하셨다). C++ 등에서는 이러하니 알아둘 것.

### 상위 클래스 생성자 및 동일 클래스 다른 생성자 호출

베이스 클래스의 생성자 또는 동일 클래스의 다른 생성자 호출하기

```java
public class Program {
    public static void main(String[] args) {
        Rectangle r;
        r = new Rectangle();
    }
}
class Shape {
    private int x, y;
    public Shape() {
        this(0, 0);
        System.out.println("Shape 생성자");
    }
    public Shape(int xloc, int yloc) {
        x = xloc; y = yloc;
        System.out.println("Shape 유인 생성자");
    }
}
class Rectangle extends Shape {
    private int width, height;
    public Rectangle() {
        this(0, 0, 0, 0);
        System.out.println("Rectangle 생성자");
    }
    public Rectangle(int x, int y, int w, int h) {
        super(x, y);
        width = w; height = h;
        System.out.println("Rectangle 유인 생성자");
    }
}
```

```
Shape 유인 생성자
Rectangle 유인 생성자
Rectangle 생성자
```

`new Rectangle()`의 실행 순서:

```
Rectangle()
  └ this(0, 0, 0, 0)              → Rectangle(int, int, int, int)
      └ super(x, y)               → Shape(int, int)        : "Shape 유인 생성자"
      └ width = w; height = h;      "Rectangle 유인 생성자"
  └ "Rectangle 생성자"
```

→ [`examples/ConstructorChainTest.java`](../examples/ConstructorChainTest.java)

> 💡 **보충:**
> - "유인 생성자"는 인수가 있는 생성자를 뜻한다.
> - ⚠ **자주 틀리는 부분:** `Shape()`는 `this(0, 0)`을 부르지만 결과에 "Shape 생성자"가 나오지 않는다. `Rectangle(int, int, int, int)`가 `super(x, y)`로 `Shape(int, int)`를 **직접** 골랐기 때문에 `Shape()`는 한 번도 불리지 않는다. (`super(...)`를 안 썼다면 컴파일러가 넣는 `super()` 때문에 `Shape()` → `this(0, 0)` 순서로 불렸을 것이다)
> - ⚠ **자주 틀리는 부분:** 한 생성자 안에서 `this(...)`와 `super(...)`를 함께 쓸 수 없다. 둘 다 "첫 문장"이어야 하기 때문이다. 그래서 `Rectangle()`은 `this(...)`로 다른 생성자에게 넘기고, 그 생성자가 `super(...)`를 부른다.
> - ⚠ **자주 틀리는 부분:** 부모에 **매개변수 없는 생성자가 없으면** 자식 생성자에서 `super(...)`를 꼭 써야 한다. 컴파일러가 넣는 `super()`가 부를 생성자가 없기 때문이다.
>   ```
>   error: constructor Shape in class Shape cannot be applied to given types;
>   ```
> - JDK 25(JEP 513)부터는 `super(...)` / `this(...)` 앞에 `this`를 쓰지 않는 문장(인수 검사 등)을 쓸 수 있다. 시험은 수업 기준 "**생성자 호출은 첫 문장**"으로 답한다. (9-3)
> - 📝 **필기 (퀴즈 3번 (7)):** `super()`로 부모 클래스 생성자를 호출해 초기화. → `Student(String name, int age, String major) { super(name, age); this.major = major; }`
