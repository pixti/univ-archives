## 1. 추상 클래스와 추상 메소드

- **추상 메소드**는 메소드 **선언만 있고 구현이 없는** 메소드다.
- `abstract`라는 키워드를 사용한다.
- 상속받는 클래스에서 내부를 구현하여 사용한다.
- 추상 메소드가 **하나라도** 있는 클래스는 클래스 앞에 `abstract` 키워드를 붙여 주어야 한다.
- 추상 클래스로부터 **객체를 생성할 수 없다.**
- 추상 메소드를 **모두 구현해야** 일반 클래스가 된다.

```java
abstract class Shape {
    abstract String getName();    // { } 대신 ; 로 끝난다
}
```

### 생각해 보기

앞의 예제(10-1의 `Shape` / `Rectangle`)에서 `Shape` 클래스 안에 아래와 같은 코드를 추가하면 어떤 일이 벌어지는가?

```java
abstract String getName();
```

1. **`Shape` 클래스 오류.** 추가한 메소드가 추상 메소드이므로 당연히 `Shape`도 추상 클래스다. 그래서 클래스명 앞에 `abstract`를 추가한다.
   ```
   error: Shape is not abstract and does not override abstract method getName() in Shape
   ```
2. **`Rectangle` 클래스도 오류.** 추상 클래스를 상속받았으므로 `Rectangle`도 추상 클래스다. 추상 메소드인 `getName` 메소드를 재정의하든지, 아니면 클래스명 앞에 `abstract` 키워드를 붙여야 한다.
   ```
   error: Rectangle is not abstract and does not override abstract method getName() in Shape
   ```
3. **추상 메소드 구현 팁:** 클래스명 밑에 빨간 줄이 생겼을 텐데, 마우스를 여기에 갖다 대면 팝업창이 뜬다. 그중에 **"Add unimplemented methods"**를 선택하면 구현해야 할 메소드의 골격이 자동으로 추가된다. (IntelliJ에서는 `Alt + Enter` → Implement methods)

→ [`examples/AbstractShapeTest.java`](../examples/AbstractShapeTest.java)

```
Shape 생성자
Rectangle 생성자
이름 : 사각형
Shape 생성자
Circle 생성자
이름 : 원
```

> 📝 **필기 (퀴즈 2번 (5)):** 추상 메서드는 `abstract`가 붙고 이게 하나라도 존재하면 그 클래스도 추상 클래스 `abstract class`로 선언되어야 한다. → **O**
> 추상 메서드(몸체 `{ }`가 없는 미완성 메서드)를 단 하나라도 포함한 클래스는 미완성 설계도라서 직접 객체를 생성(인스턴스화)할 수 없다. 그래서 컴파일러는 반드시 `abstract`를 붙이도록 강제한다.

> 📝 **필기 (퀴즈 2번 (6)):** 추상 클래스를 상속할 경우, 자식 클래스도 추상 클래스로 선언하든지 아니면 부모 클래스의 추상 메서드를 재정의해 주면 된다. → **O**
> 추상 클래스를 상속받은 자식 클래스는 부모의 "추상 메서드"까지 그대로 물려받는다. 선택지는 딱 두 가지다.
> 1. 물려받은 **모든** 추상 메서드를 오버라이딩(재정의)하여 몸체(`{ }`)를 구현하고 일반 클래스가 되거나,
> 2. 구현하지 않은 추상 메서드가 남아 있다면 자식 클래스 자신도 `abstract`를 붙여 추상 클래스로 선언한다.

> 💡 **보충:**
> - 추상 클래스도 일반 필드, 일반 메소드, **생성자**를 가질 수 있다. 생성자는 `new Shape()`로 직접 부를 수 없지만, 자식 객체를 만들 때 `super()`로 불린다. (실습 2번 [`EmployeeSalaryTest.java`](../practice/inheritance2/EmployeeSalaryTest.java))
> - 추상 클래스 타입의 **변수**는 만들 수 있다. `Shape s = new Rectangle();` → 실제 객체의 `getName()`이 실행된다(10-3 동적 바인딩).
> - ⚠ **자주 틀리는 부분:** 추상 메소드에는 `private`를 붙일 수 없다. 자식이 물려받아 구현해야 하는데 `private`로 막으면 자식이 볼 수 없기 때문이다.
>   ```
>   error: illegal combination of modifiers: abstract and private
>   ```
>   그래서 보통 `public`(또는 `protected`, default)으로 선언한다. 자세한 설명은 실습 3번 [`VehicleEngineTest.java`](../practice/inheritance2/VehicleEngineTest.java)의 📝 필기.

## 2. 인터페이스

- **모든 메소드가 다 추상 메소드**인 클래스다.
- 객체가 가져야 할 **기능만을 명시**한 것이다.
- 추상 클래스와 같이 인터페이스로 객체를 생성할 수 없다.

```java
public interface IShape {
    public double area();
    public double volume();
    public String getName();
}
class MyShape implements IShape {   // 상속과 다르게 implements 키워드 사용
    public double area() {...}
    public double volume() {...}
    public String getName() {...}
}
```

- **일반 필드는 불가**, `static final` 필드는 허용한다. (선언과 동시에 초기화)
- **일반 메소드는 불가**, `static` 메소드는 허용한다. (`static`이 없으면 컴파일 에러)

```java
public interface IShape {
    int x = 3;          // => static final int x = 3 으로 변경됨
    public double area();
    public double volume();
    public String getName();
    public void print() { System.out.println("hoho"); }          // 불가
}
```

```java
public interface IShape {
    static final int x = 3;
    public double area();
    public double volume();
    public String getName();
    public static void print() { System.out.println("hoho"); }   // static 메소드는 허용
}
```

```
error: interface abstract methods cannot have body      ← 위의 "불가" 코드
```

→ [`examples/InterfaceTest.java`](../examples/InterfaceTest.java)

```
이름 : 정육면체 (한 변 2.0)
겉넓이 : 24.0
부피 : 8.0
IShape.x = 3
hoho
기본 구현 : 정육면체 (한 변 2.0)
```

> 📝 **필기 (퀴즈 2번 (7)):** "인터페이스 안에는 필드는 올 수 없고 추상 메소드만 올 수 있다" → **X**
> 모든 메서드들이 추상 메서드 `abstract`인 형태라고 보면 된다. 메소드만 선언하는 게 아니라 필드도 올 수 있지만, 일반 필드가 아니라 `static` 필드만 올 수 있다.
> 인터페이스 안에는 추상 메서드뿐만 아니라 상수 필드(`public static final`)가 올 수 있다. 또한 Java 8부터는 몸체가 있는 디폴트 메서드(`default`)와 정적 메서드(`static`)도 넣을 수 있게 확장되었다.

> 📝 **필기 (퀴즈 2번 (8)):** "인터페이스에는 정적 메소드는 올 수 있다" → **O**
> Java 8부터 인터페이스 안에 `static` 메서드를 선언하고 구현할 수 있다. 구현 클래스의 객체 없이도 `인터페이스이름.정적메서드()` 형태로 유틸리티성 메서드를 호출할 수 있다.

> 📝 **필기 (퀴즈 2번 (9)):** "인터페이스에는 일반 필드는 허용되지 않지만 `final` 필드는 허용된다. 그래서 일반 필드처럼 선언해도 내부적으로 `final`로 취급되며, 필드 선언 시 초기화해야 한다" → **O**
> 인터페이스는 객체를 생성할 수 없으므로 객체마다 가지는 인스턴스 변수는 선언할 수 없고 상수만 선언할 수 있다. `int MAX = 10;`처럼 써도 컴파일러가 `public static final int MAX = 10;`으로 취급한다. `final` 상수는 값을 바꿀 수 없으므로 반드시 선언과 동시에 초기값을 지정해야 한다.

> 💡 **보충:**
> - 인터페이스 안에서는 `public`, `abstract`, `static final`을 안 써도 자동으로 붙는다.
>   ```java
>   double area();      // ⇒ public abstract double area();
>   int x = 3;          // ⇒ public static final int x = 3;
>   ```
> - ⚠ **자주 틀리는 부분:** 그래서 구현하는 클래스의 메소드는 **반드시 `public`**이어야 한다. `public`을 빼면 부모(인터페이스)보다 접근 범위가 좁아져 오류가 난다.
>   ```
>   error: area() in MyShape cannot implement area() in IShape
>     attempting to assign weaker access privileges; was public
>   ```
> - Java 8부터 인터페이스에도 몸체가 있는 메소드를 넣을 수 있다. 단, `default`나 `static`을 붙여야 한다.
>   ```java
>   default void hello() { System.out.println("기본 구현 : " + getName()); }
>   ```
>   그래서 "인터페이스에는 일반 메소드가 없다"는 Java 7까지의 설명이다. 시험은 수업 기준으로 답한다.
> - `x`는 `static final`이므로 `IShape.x`로 쓰고, 값을 바꿀 수 없다.

## 3. 추상 클래스와 인터페이스의 공통점과 차이점

- 추상 클래스와 인터페이스는 **객체를 생성할 수 없다.**
- 파생 클래스에서 추상 메소드를 **모두 구현**해 주어야만 일반 클래스가 된다.
- 추상 클래스의 모든 메소드가 추상 메소드이면 인터페이스로 바꿀 수 있다.
- 추상 클래스에는 일반 메소드가 있을 수 있다. (인터페이스는 없음)
- 인터페이스는 **다중 상속을 지원**한다. (추상 클래스는 불가)
- 추상 클래스 하나와 인터페이스 여러 개를 함께 상속할 수 있다.

```java
class B extends A implements IShape {
    ...
}
```

> 💡 **보충: 한눈에 비교**
>
> | | 추상 클래스 | 인터페이스 |
> |---|---|---|
> | 키워드 | `abstract class` | `interface` |
> | 상속 / 구현 | `extends` (하나만) | `implements` (여러 개 가능) |
> | 객체 생성 | 불가 | 불가 |
> | 필드 | 일반 필드 가능 | 상수(`public static final`)만 |
> | 메소드 | 일반 메소드 + 추상 메소드 | 추상 메소드 (+ Java 8 `default` · `static`) |
> | 생성자 | 있을 수 있음 | 없음 |
> | 쓰는 경우 | 자식들이 공통 필드 · 코드를 공유할 때 ("~이다" 관계) | 서로 다른 클래스에 같은 기능 규격을 정할 때 ("~할 수 있다") |
>
> - 인터페이스끼리는 `extends`로 상속한다. 여러 개도 가능하다: `interface ITruck extends Car, Other { }`

## 4. 인터페이스를 이용한 다중 상속

```java
public class A {
    public void f1() {…};
    public void f2() {…};
}
public class B implements IB {
    public void g1() {…};
    public void g2() {…};
}
interface IB {
    public void g1();
    public void g2();
}
public class C extends A implements IB {   // 다중 상속의 예
    private B ob = new B();
    public void g1() { ob.g1(); }
    public void g2() { ob.g2(); }
    public void h1() {…};
    public void h2() {…};
}
```

```
class A { f1(), f2() }          interface IB { g1(), g2() }
      ▲                                ▲               ▲
      │ extends                        │ implements    │ implements
class C extends A implements IB ───────┘         class B implements IB
  - ob = new B()  ────────────────────────────────▶ (B 객체를 필드로 가짐)
  - g1() { ob.g1(); }   g2() { ob.g2(); }  → B 에게 맡김
  - h1(), h2()          → C 에 새로 추가
```

- 자바는 클래스 두 개를 `extends`할 수 없다(`class C extends A, B` → ❌).
- 대신 클래스 하나(`A`)를 상속하고 인터페이스(`IB`)를 구현한다. 인터페이스의 메소드는 그 인터페이스를 이미 구현한 클래스 `B`의 객체를 필드로 두고 **일을 맡긴다**.
- 결과적으로 `C`는 `A`의 기능(`f1`, `f2`)은 상속으로, `B`의 기능(`g1`, `g2`)은 포함으로 가진다. `C`는 `A` 타입으로도, `IB` 타입으로도 쓸 수 있다.

→ [`examples/InterfaceMultipleInheritance.java`](../examples/InterfaceMultipleInheritance.java)

> 💡 **보충:**
> - `public class`는 파일마다 하나라서 실제로는 `A`, `B`, `C`를 각각 다른 파일에 둬야 한다.
> - 이렇게 다른 객체에게 일을 맡기는 것을 **위임(delegation)**이라고 한다.

## 5. [실습] 자바를 이용하여 다중 상속 구현하기

픽업트럭(`Pickup`)은 승용차(`PassengerCar`)이면서 트럭이기도 하다. 승용차는 상속하고, 트럭 기능은 인터페이스 `ITruck`으로 구현한다.

```java
interface Car {
    public void showInfo();
}
class PassengerCar implements Car {
    private int seats; // 정원
    public PassengerCar() { seats = 2; }
    public PassengerCar(int n) { seats = n; }
    public int getSeats() { return seats; }
    public void setSeats(int n) { seats = n; }
    public void showInfo() { System.out.println("좌석 수 : " + seats); }
}
interface ITruck extends Car {
    public int getPayload();
    public void setPayload(int w);
};
```

```java
class Truck implements ITruck {
    private int payload;
    public Truck() { payload = 100; }
    public Truck(int w) { payload = w; }
    public int getPayload() { return payload; }
    public void setPayload(int w) { payload = w; }
    public void showInfo() { System.out.println("적재 하중 : " + payload); }
}
```

```java
class Pickup extends PassengerCar implements ITruck {
    private int tow_capacity; // 견인 능력
    Truck truck;
    public Pickup() { super(4); truck = new Truck(1000); tow_capacity = 10000; }
    public Pickup(int s, int w, int c)
        { super(s); truck = new Truck(w); tow_capacity = c; }
    public void setCapacity(int c) { tow_capacity = c; }
    public int getCapacity() { return tow_capacity; }
    public void showInfo() { System.out.println("좌석 수 : " + getSeats() + ", 적재 하중 : " + getPayload() + ", 견인 능력 : " + tow_capacity); }
    @Override
    public int getPayload() { return truck.getPayload(); }
    @Override
    public void setPayload(int w) { truck.setPayload(w); }
}
```

```java
public class MultipleInheritanceTest {
    public static void main(String[] args) {
        Car[] cars = new Car[3];
        cars[0] = new PassengerCar();
        cars[1] = new Truck(500);
        cars[2] = new Pickup(4, 2000, 10000);
        for (int i = 0; i < 3; i++) {
            cars[i].showInfo();
        }
    }
}
```

```
좌석 수 : 2
적재 하중 : 500
좌석 수 : 4, 적재 하중 : 2000, 견인 능력 : 10000
```

→ [`examples/MultipleInheritanceTest.java`](../examples/MultipleInheritanceTest.java)

```
interface Car { showInfo() }
    ▲ implements                      ▲ extends
class PassengerCar                 interface ITruck { getPayload(), setPayload() }
    ▲ extends                          ▲ implements            ▲ implements
class Pickup ──────────────────────────┘                    class Truck
  └ Truck truck (필드) ─────────────────────────────────────────▶ 일을 맡김
```

> 💡 **보충:**
> - `interface ITruck extends Car`: 인터페이스끼리는 `extends`로 상속한다. 그래서 `Truck`과 `Pickup`은 `ITruck`의 메소드와 `Car`의 `showInfo()`를 **모두** 구현해야 한다.
> - `interface ITruck { … };`처럼 닫는 중괄호 뒤의 `;`는 무시되므로 오류는 아니지만 보통 쓰지 않는다.
> - `Pickup`의 `showInfo()`는 `getSeats()`(`PassengerCar`에게서 상속)와 `getPayload()`(`truck`에게 맡김)를 함께 쓴다. `seats`는 `PassengerCar`의 `private` 필드라서 `Pickup`에서 직접 쓸 수 없다.
> - `Car` 타입 배열 하나에 세 종류의 차를 모두 넣고 `showInfo()`를 부르면, 실제 객체의 `showInfo()`가 실행된다. 이것이 10-3의 **동적 바인딩**이다.
