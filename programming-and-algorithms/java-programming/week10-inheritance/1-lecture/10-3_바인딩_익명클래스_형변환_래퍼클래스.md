## 1. 상속과 바인딩

- **필드는 정적 바인딩**: 컴파일 시에 (변수의) 타입을 보고 결정한다.
- **메소드는 동적 바인딩**: 실행 시에 객체의 타입에 따라 결정한다.

```java
class A {
    public int X = 2;
    public void f() { System.out.println("kkk"); }
}
class B extends A {
    public int X = 0;
    public void f() { System.out.println("hhh"); }
}
public class Test {
    public static void main(String[] args) {
        A c = new B();
        System.out.println(c.X); // A에서 상속받은 X -> (정적 바인딩)
        c.f();                   // B의 f() -> (동적 바인딩)
    }
}
```

```
hhh
```

### 상속과 바인딩 – static

- 정적 필드, 정적 메소드는 **모두 정적 바인딩**(컴파일 시 결정)이다.

```java
class A {
    public static int X = 2;
    public static void f() { System.out.println("kkk"); }
}
class B extends A {
    public static int X = 0;
    public static void f() { System.out.println("hhh"); }
}
public class Test {
    public static void main(String[] args) {
        A c = new B();
        System.out.println(c.X); // A의 X
        c.f();                   // A의 f()
    }
}
```

> 📝 **필기 (퀴즈): 자바는 동적 바인딩**
> **질문:** 자바는 동적 바인딩이면 동적 타입 언어인가? → **아니다.** 자바는 대표적인 **정적 타입(Statically Typed) 언어**다. 다만 객체지향의 다형성을 구현할 때 **동적 바인딩(Dynamic Binding)**을 쓰기 때문에 용어가 비슷해 헷갈리기 쉽다.
> 1. **정적 타입 언어로서의 자바 (Static Typing)**
>    - 변수를 선언할 때 자료형(`int`, `String`, `Human` 등)을 명시해야 하며, **컴파일 시점**에 변수의 타입이 결정되고 타입 검사가 이루어진다.
>    - 한 번 선언된 변수의 타입은 실행 중에 바뀔 수 없으며, 맞지 않는 타입의 값을 대입하면 컴파일 에러가 발생한다.
>      ```java
>      int age = 10;
>      age = "열살"; // 컴파일 에러 발생 (정적 타입 검사)
>      ```
>    - (참고: 파이썬이나 자바스크립트처럼 변수 선언 시 타입을 적지 않고 실행 시점에 타입이 결정되는 언어가 "동적 타입 언어"다)
> 2. **동적 바인딩 (Dynamic Binding)과의 차이**: 자바는 정적 타입 언어이지만, 상속 관계에서 메서드를 호출할 때는 동적 바인딩을 쓴다.
>    ```java
>    Human h = new Student("철수", 20, "컴퓨터");
>    h.print();
>    ```
>    - **정적 타입 결정 (컴파일 시점):** 컴파일러는 참조 변수 `h`의 타입을 `Human`으로 고정하고, `Human` 클래스에 `print()` 메서드가 존재하는지만 검사한다.
>    - **동적 바인딩 (실행 시점):** 프로그램이 실제로 실행될 때 JVM이 `h`가 가리키는 실제 객체가 `Student`임을 확인하고, 부모(`Human`)가 아닌 자식(`Student`)이 재정의한 `print()`를 연결하여 실행한다.
>
> **요약**
> - 언어의 타입 시스템: **정적 타입** (컴파일 시점에 변수의 자료형 결정 및 검사)
> - 오버라이딩된 메서드 호출 방식: **동적 바인딩** (실행 시점에 실제 객체의 메서드 연결)
>
> 📝 실제 돌아갈 때는 상위 타입의 변수에 대해서 상위 타입 메소드를 호출하는 게 아니라 **객체가 뭐냐에 따라서 결정**.

> 💡 **보충:**
> - ⚠ **자주 틀리는 부분:** 필드는 재정의되지 않는다. `B`에 같은 이름의 `X`를 만들면 `A`의 `X`를 **가릴(hide)** 뿐이고, `B` 객체 안에는 `A`의 `X`(2)와 `B`의 `X`(0)가 둘 다 들어 있다. 어느 `X`를 쓸지는 **변수의 타입**이 정한다. `((B) c).X`는 0이다. 그래서 부모와 자식에 같은 이름의 필드를 만들지 않는 것이 좋다.
> - static 메소드는 객체가 아니라 **클래스**에 속한다. `c.f()`라고 써도 컴파일러는 변수 `c`의 타입(`A`)만 보고 `A.f()`로 바꿔 호출한다. 그래서 static 멤버는 `A.X`, `B.f()`처럼 **클래스 이름으로** 쓰는 것이 좋다.
> - ⚠ **자주 틀리는 부분:** `B`의 static `f()`는 `A`의 `f()`를 재정의(override)한 것이 아니라 **숨긴(hide)** 것이다. static 메소드에 `@Override`를 붙이면 컴파일 오류가 난다.

## 2. 익명 내부 클래스

- **클래스명이 없는** 클래스다.
- 익명 내부 클래스는 **선언과 함께 객체 생성이 동시에** 된다.
- 보통 기존 클래스의 메소드를 재정의할 경우, 또는 인터페이스를 구현할 경우에 쓴다.

```java
MyInterface an_inner = new MyInterface() {
    public void test() {
        ........
        ........
    }
};
```

### 익명 클래스를 사용한 경우

```java
interface MyInterface {
    public void test();
}
// 인터페이스 구현하는 익명 클래스를 정의함과 동시에 객체를 생성
public class AnonymousTest {
    public static void main(String[] args) {
        MyInterface inner = new MyInterface() {
            public void test() {
                System.out.println("테스트입니다.");
            }
        };
        inner.test();
    }
}
```

### 익명 클래스를 사용하지 않았을 경우

```java
interface MyInterface {
    public void test();
}
class MyClass implements MyInterface {
    public void test() {
        System.out.println("테스트입니다.");
    }
}
public class AnonymousTest {
    public static void main(String[] args) {
        MyClass inner = new MyClass();
        inner.test();
    }
}
```

```
테스트입니다.
```

### 생성과 동시에 인수로 사용

```java
interface Greeting {
    String message();
}
public class AnonymousTest {
    public void display(Greeting g) {
        System.out.println(g.message());
    }
    public static void main(String args[]) {
        AnonymousTest ob = new AnonymousTest();

        ob.display(new Greeting() { // 생성과 동시에 인수로 사용
            public String message() {
                return "안녕하세요";
            }
        });
    }
}
```


> ⚠ **자주 틀리는 부분:**
> - 강의 코드의 `Interface MyInterface`처럼 대문자로 쓰면 컴파일 오류다. 자바의 키워드는 모두 소문자 **`interface`**다. 위 코드는 고쳐서 실었다.
> - 익명 클래스는 마지막이 **`};`**로 끝난다. 클래스 몸체를 닫는 `}`와 대입문을 끝내는 `;`를 둘 다 써야 한다. 인수로 넘길 때는 `});` (`}` 몸체, `)` 메소드 호출 괄호, `;` 문장 끝)다.

> 💡 **보충:**
> - 한 번만 쓰고 말 클래스라면 이름을 붙여 따로 만들지 않고 익명 클래스로 바로 만들면 코드가 짧아진다.
> - 익명 클래스도 컴파일하면 `AnonymousTest$1.class`처럼 번호가 붙은 클래스 파일이 따로 생긴다. "이름이 없다"는 것은 코드에서 부를 이름이 없다는 뜻이다.
> - 인터페이스의 메소드는 `public`이므로 익명 클래스 안의 `test()`도 `public`이어야 한다.
> - `display`는 static이 아닌 인스턴스 메소드라서, static `main`에서 부르려면 먼저 객체 `ob`를 만든다.
> - 메소드가 하나뿐인 인터페이스는 Java 8의 **람다식**으로 더 짧게 쓸 수 있다.
>   ```java
>   MyInterface inner3 = () -> System.out.println("람다식 테스트입니다.");
>   ob.display(() -> "반갑습니다");
>   ```

## 3. 클래스 형변환 (Type Casting)

- 하위 클래스에서 상위 클래스로의 변환은 **묵시적**이다.
- 상위 클래스에서 하위 클래스로의 변환은 **명시적(강제적)**이다.
- 필드에 대한 접근은 **객체 변수의 타입**에 의해 결정된다.
- 메소드 호출은 **실제 저장된 인스턴스의 타입**에 의해 결정된다.

```java
class Poly
{   ...   }
class Square extends Poly
{   ...   }
public class Program
{
    public static void main(String[] args)
    {
        Square x = (Square) new Poly(); // 명시적
        Poly y = new Square();          // 묵시적
    }
}
```

> ⚠ **자주 틀리는 부분:** `Square x = (Square) new Poly();`는 **명시적 형변환을 쓰는 문법의 예**일 뿐, 실제로 실행하면 `ClassCastException`이 난다. `new Poly()`로 만든 객체는 `Square`가 아니기 때문이다. 아래 (2)의 `B p = (B) new A();`와 같은 경우다. 다운캐스팅은 **원래 하위 타입이었던 객체**를 되돌릴 때만 성공한다.

### (1) [실습] 하위 타입의 객체를 상위 타입의 변수에 저장하기

```java
class A {
    public int x = 53;
    public void print() {
        System.out.println("Parent method :" + x);
    }
}
class B extends A {
    public int x = 17;
    public String y = "abc";
    public void print() {
        System.out.println("Child method :" + x);
        System.out.println("Child method :" + y);
    }
}
public class Example {
    public static void main(String arg[]) {
        A p = new B();
        p.print();                                    // B의 메소드 호출
        System.out.println("Parent value : " + p.x);  // A의 필드 접근
    }
}
```

```
Child method :17
Child method :abc
Parent value : 53
```

### (2) [실습] 상위 타입의 객체를 하위 타입의 변수에 저장하기

```java
public class Example {
    public static void main(String arg[]) {
        B p = (B) new A(); // 컴파일 오류 아님. 실행 오류
        p.print();
        System.out.println("Child value : " + p.x);
    }
}
```

```
Exception in thread "main" java.lang.ClassCastException: class A cannot be cast to class B
```

```java
// 아래의 형태는 허용
public class Example {
    public static void main(String arg[]) {
        A p = new B();
        B c = (B) p;
        c.print();
        System.out.println("Child value : " + c.x);
    }
}
```

```
Child method :17
Child method :abc
Child value : 17
```

→ (1), (2)와 `Poly` / `Square`를 한 파일로: [`code/TypeCastingTest.java`](code/TypeCastingTest.java)

> 💡 **보충:**
> - 업캐스팅한 변수로는 **부모에 있는 것만** 쓸 수 있다. `A p = new B();`에서 `p.y`는 컴파일 오류다(`A`에는 `y`가 없다).
>   ```
>   error: cannot find symbol
>     symbol:   variable y
>     location: variable p of type A
>   ```
> - 업캐스팅을 쓰는 이유: 서로 다른 자식 객체들을 부모 타입 하나로 묶어서(배열, 매개변수) 똑같이 다룰 수 있기 때문이다. (10-2 실습의 `Car[] cars`, 퀴즈 3번의 `Human[] arr`)
> - 📝 **필기 (퀴즈):** 상위 클래스 (변수에) 하위 타입 객체를 저장할 수 있다. new Human 으로 작성도 가능. 자식 클래스에서 오버라이딩 가능. 부모 기능 그대로 가져다 쓰려면 super.
>   1. **업캐스팅(Upcasting):** 상위 클래스(`Human`) 타입의 변수나 배열에 하위 클래스(`Student`) 타입의 객체를 저장할 수 있다.
>   2. **오버라이딩과 `super`:** 자식 클래스에서 부모의 메서드를 재정의할 수 있으며, 부모에 구현된 기존 기능을 그대로 가져다 쓰려면 `super.메서드()`를 호출한다.
>   3. **동적 바인딩:** 실제 프로그램이 실행될 때는 변수의 선언 타입(`Human`)이 아니라, 그 변수에 실제로 저장된 객체가 무엇인지(`Student`)에 따라 호출될 메서드가 결정된다.
>   ```java
>   Human[] arr = new Human[3];                    // 1. 상위 클래스(Human) 타입의 배열 생성
>   arr[0] = new Student("순이", 10, "식품");        // 2. 상위 타입 배열에 하위 타입 객체 저장 (업캐스팅)
>   arr[1] = new Student("철수", 20, "컴퓨터");
>   arr[2] = new Student("바둑이", 21, "철학");
>   for (Human e : arr) {
>       e.print();                                 // 3. Student 에서 오버라이딩한 print() 가 호출됨 (동적 바인딩)
>   }
>   ```

## 4. 인터페이스의 형변환

- 인터페이스로 객체를 생성하지는 못하지만, 인터페이스 유형의 객체 참조 변수에 **인터페이스를 구현하고 있는 클래스 객체**를 할당할 수 있다.
- 클래스 형변환과 마찬가지로, 인터페이스 유형의 객체 참조 변수는 **인터페이스에 선언된 요소에만** 접근할 수 있다.

```java
public class Example {
    public static void main(String[] args) {
        IA p = new A();
        p.print();
        System.out.println("x : " + p.x); // 접근 불가능
    }
}
interface IA {
    public void print();
}
class A implements IA {
    public int x = 17;
    public String y = "abc";
    public void print() {
        System.out.println("print method :" + x);
        System.out.println("print method :" + y);
    }
}
```

```
error: cannot find symbol
  symbol:   variable x
  location: variable p of type IA
```

## 5. instanceof 연산자

- 주로 **조건문**에 쓴다.
- 왼쪽에는 레퍼런스 변수, 오른쪽에는 타입(클래스명) 피연산자가 온다.
- 연산 결과로 `boolean` 값인 `true`, `false` 중 하나를 반환한다.
- 실제 인스턴스와 같은 타입뿐만 아니라 **조상 타입에 대해서도 `true`**를 반환한다. 따라서 `instanceof` 연산의 결과가 `true`라는 것은 **검사한 타입으로 형변환이 가능하다**는 것을 뜻한다.

### [실습] instanceof 연산자 사용하기

```java
class Class1 {}
class Class2 {}
class IsTest {
    static void test(Object o) {
        Class1 ob1;
        Class2 ob2;
        if (o instanceof Class1) {
            System.out.println("o is Class1");
            ob1 = (Class1) o;
        }
        else if (o instanceof Class2) {
            System.out.println("o is Class2");
            ob2 = (Class2) o;
        }
        else { System.out.println("o is neither Class1 nor Class2."); }
    }
    public static void main(String[] args)
    {
        Class1 c1 = new Class1();
        Class2 c2 = new Class2();
        test(c1);         // if문
        test(c2);         // else if문
        test("a string"); // else 문
    }
}
```

```
o is Class1
o is Class2
o is neither Class1 nor Class2.
```

→ [`code/IsTest.java`](code/IsTest.java)

> 💡 **보충:**
> - 마지막 줄은 코드대로 **마침표까지** 출력된다. (강의 자료의 실행 결과에는 마침표가 빠져 있다)
> - `test(Object o)`: `Object`는 모든 클래스의 조상이므로 어떤 객체든(`Class1`, `Class2`, `String`) 받을 수 있다. 그래서 `c1 instanceof Object`는 항상 `true`다.
> - `null instanceof 아무타입`은 항상 `false`다. `instanceof` 검사를 통과하면 `null`이 아님도 보장된다.
> - Java 16부터는 검사와 형변환을 한 번에 쓸 수 있다(패턴 매칭): `if (o instanceof Class1 ob1) { … }`
> - 다운캐스팅 전에 `instanceof`로 검사하면 3절의 `ClassCastException`을 피할 수 있다.

## 6. Wrapper 클래스

- 기본형 타입을 **객체로 사용해야 하는 경우**에 쓴다.
- Wrapper 클래스는 기본형 자료에 대한 메소드를 제공한다.

| 기본형 | Wrapper 클래스 |
|---|---|
| `int` | `Integer` |
| `double` | `Double` |
| `byte` | `Byte` |
| `short` | `Short` |
| `long` | `Long` |
| `float` | `Float` |
| `char` | `Character` |
| `boolean` | `Boolean` |
| `void` | `Void` |

- `Void` 클래스는 실체화될 수 없으며 단지 공 참조(`null`) 개념이다.
- `Void`를 제외한 포장 클래스의 생성자는 저장할 기본형 타입 값을 인수로 받는다.
- 포장 클래스는 다양한 메소드 및 상수를 제공한다.
  - 예를 들어 `Integer.MAX_VALUE`는 int형 변수가 가질 수 있는 최대값을, `Integer.MIN_VALUE`는 최소값을, `Integer.SIZE`는 int형 변수의 비트 크기를 나타낸다.

### boxing과 unboxing

- **boxing**: 기본 자료형을 포장 클래스로 변환
- **unboxing**: 포장 클래스를 기본 자료형으로 변환

```java
Integer iObj = new Integer(30);   // boxing 과정
int age2 = iObj.intValue();       // unboxing 과정
```

- JDK 1.5 버전 이후는 자동으로 boxing, unboxing이 처리되도록 **autoboxing, autounboxing**을 제공한다.

```java
int i = 123;
Integer o = i;   // autoboxing
int j = o;       // autounboxing
```

```
 i  [ 123 ]
 o  [  ●──]──────▶ ┌───────┐
                   │  int  │
                   │  123  │
                   └───────┘
 j  [ 123 ]
```

- autoboxing과 autounboxing은 **기본형 타입과 그에 상응하는 포장 클래스에서만** 일어난다. 다른 경우 컴파일 에러가 발생한다.

```java
Double dObj = 1.23;
int n2 = dObj;              // 오류 발생
int n = dObj.intValue();
```

```
error: incompatible types: Double cannot be converted to int
```

### [실습] boxing과 unboxing

```java
public class BoxingUnBoxingTest {
    public static void main(String[] args) {
        int val = 30;
        Integer iOb = Integer.valueOf(val); // boxing
        Integer jOb = val;                  // autoboxing

        System.out.println(val + " " + iOb + " " + jOb);

        Integer ob = new Integer(5);
        int i = ob.intValue();              // unboxing
        int j = ob;                         // autounboxing

        System.out.println(ob + " " + i + " " + j);
    }
}
```

```
30 30 30
5 5 5
```

→ [`code/BoxingUnBoxingTest.java`](code/BoxingUnBoxingTest.java)

> ⚠ **자주 틀리는 부분:**
> - `new Integer(30)`, `new Integer(5)`처럼 포장 클래스의 **생성자를 쓰는 방법은 JDK 9부터 deprecated**(사용 자제)다. JDK 25에서도 컴파일은 되지만 "uses or overrides a deprecated API" 안내가 나온다. `Integer.valueOf(30)` 또는 autoboxing을 쓴다. 예제 코드는 `Integer.valueOf`로 바꿨다.
> - `null`인 포장 객체를 autounboxing하면 `NullPointerException`이 난다. `Integer none = null; int k = none;`은 `none.intValue()`를 부르는 것과 같기 때문이다.
> - 포장 객체끼리 값을 비교할 때는 `==`가 아니라 **`equals()`**를 쓴다. `==`는 참조(주소) 비교다. (`String`과 같은 이유)

> 💡 **보충:**
> - autoboxing은 컴파일러가 `Integer.valueOf(val)`로, autounboxing은 `ob.intValue()`로 바꿔 주는 것이다.
> - `println`에 포장 객체를 넣으면 `toString()`이 불려 안의 값이 출력된다.
> - `int n = dObj.intValue();`는 소수점 이하를 버려서 1이 된다.
> - 포장 클래스가 필요한 대표적인 곳: `ArrayList<Integer>`처럼 **객체만 담을 수 있는 컬렉션**, `null`이 필요한 값.
> - `Integer.parseInt("123")`처럼 문자열을 기본형으로 바꾸는 static 메소드도 포장 클래스에 있다.
