## 1. 기본 예외 처리 (Exception Handling)

- 예외 처리는 프로그램의 정상적인 흐름을 방해하는 예외들을 **조치하여 계속 프로그램이 진행될 수 있게** 하는 것이 목적이다.
- `try-catch` 문을 사용한다.
  - `try` 블록에는 예외 발생 가능한 코드가 포함된다.
  - `catch` 블록은 `try` 블록에서 발생한 exception을 처리한다.

```java
public class Example {
    public static void main(String args[])
    {
        Scanner sc = new Scanner(System.in);
        int a = sc.nextInt();
        int b = sc.nextInt();
        int c;                     // ✅ try 바깥에서 선언
        try {
            c = a / b;             // divide-by-zero 예외 발생 가능
        }
        catch (ArithmeticException e) {
            c = -1;
        }
        System.out.println("결과는 " + c + "입니다.");
    }
}
```

```
(입력 : 10 0)  결과는 -1입니다.
(입력 : 10 3)  결과는 3입니다.
```

→ [`examples/DivideExample.java`](../examples/DivideExample.java)

> ⚠ **자주 틀리는 부분:** 강의 코드는 `int c = a / b;`처럼 `c`를 **`try` 블록 안에서** 선언한다. 그러면 `catch` 블록과 그 아래 `println`에서 `c`를 찾을 수 없어 컴파일 오류가 난다(`error: cannot find symbol`). 변수의 유효 범위는 선언한 블록 `{ }` 안이다(7강). `try`, `catch`, 그 아래에서 모두 쓰려면 위처럼 **`try` 앞에서 선언**한다.

> 💡 **보충:**
> - `try-catch`가 없으면 예외가 난 순간 프로그램이 멈추고 다음 메시지가 출력된다.
>   ```
>   Exception in thread "main" java.lang.ArithmeticException: / by zero
>   ```
> - 0으로 나누기 예외는 **정수** 나눗셈에서만 난다. 실수(`double`)를 0으로 나누면 예외 없이 `Infinity`나 `NaN`이 된다(`5.0 / 0` → `Infinity`).
> - 컴파일 오류는 실행하기 전에 잡히는 **문법** 오류이고, 예외는 **실행 중**에 생기는 오류다. `try-catch`로는 컴파일 오류를 처리할 수 없다.

## 2. finally 블록

- `finally` 블록이 추가로 올 수 있다.
- `try` 블록에서 할당된 리소스를 정리하고, **예외 발생 여부에 관계없이 항상 실행해야 하는 코드**를 기술한다.

```java
try
{
    // try block
}
catch (Exception arg) {
    // catch block
}
finally {
    // finally block
}
```

### [실습] finally 블록 – 예외가 발생하지 않은 경우

```java
class FinallyTest {
    public static void main(String args[]) {
        try {
            System.out.println("First statement of try block");
            int num = 3;
            System.out.println(num);
        }
        catch (ArithmeticException e) {
            System.out.println("ArithmeticException");
        }
        finally {   // 예외발생 없이도 실행됨
            System.out.println("finally 블록 내 ...");
        }
        System.out.println("try-catch 블락 밖 ...");
    }
}
```

```
First statement of try block
3
finally 블록 내 ...
try-catch 블락 밖 ...
```

> ⚠ **자주 틀리는 부분:** 강의 코드는 `int num = 3.14;`다. 이 줄은 컴파일 오류다(`possible lossy conversion from double to int`, 2강). "예외가 나지 않는 코드"의 예로 쓰려면 `int num = 3;`처럼 정수를 쓰거나 `(int) 3.14`로 형변환한다. 위 코드는 `int num = 3;`으로 고쳤다.

### [실습] finally 블록 – 예외가 발생한 경우

```java
class FinallyTest {
    public static void main(String args[]) {
        try {
            System.out.println("First statement of try block");
            int num = 5 / 0;   // 예외 발생
            System.out.println(num);
        }
        catch (ArithmeticException e) {
            System.out.println("ArithmeticException");
        }
        finally {
            System.out.println("finally 블록 내 ...");
        }
        System.out.println("try-catch 블락 밖 ...");
    }
}
```

```
First statement of try block
ArithmeticException
finally 블록 내 ...
try-catch 블락 밖 ...
```

### [실습] finally 블록 – catch문과 일치하지 않는 예외

```java
class FinallyTest {
    public static void main(String args[]) {
        try {
            System.out.println("First statement of try block");
            throw new ArrayIndexOutOfBoundsException();
        }
        catch (ArithmeticException e) {
            System.out.println("ArithmeticException");
        }
        finally {
            System.out.println("finally 블록 내 ...");
        }
        System.out.println("try-catch 블락 밖 ...");
    }
}
```

```
First statement of try block
finally 블록 내 ...
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException
	at FinallyTest.main(FinallyTest.java:5)
```

→ 세 경우를 한 파일로: [`examples/FinallyTest.java`](../examples/FinallyTest.java)

> 💡 **보충: 세 경우의 흐름 비교**
>
> | 경우 | 실행 순서 | "try-catch 블락 밖" |
> |---|---|:-:|
> | 예외 없음 | `try` 끝까지 → (`catch` 건너뜀) → `finally` → 다음 줄 | 출력 |
> | 예외 발생, `catch`와 일치 | `try` 중단 → `catch` → `finally` → 다음 줄 | 출력 |
> | 예외 발생, `catch`와 불일치 | `try` 중단 → (맞는 `catch` 없음) → `finally` → **예외가 메소드 밖으로 전달** | 출력 안 됨 |
>
> - 세 번째 경우 `main`에서 예외가 빠져나가면 프로그램이 비정상 종료된다. 그래도 **`finally`는 실행된다.**
> - `finally`는 `try`나 `catch` 안에서 `return`을 만나도 실행된다. 그래서 `Scanner`·파일 닫기 같은 자원 정리를 넣는다.
> - `throw new ArrayIndexOutOfBoundsException();`은 실제 배열 없이 예외를 직접 발생시킨 것이다(`throw`는 11-2).

## 3. 예외 처리 순서

- `try-catch` 문에서 **여러 `catch`문**을 사용할 수 있다.
- `catch`문은 **순서대로** 검사한다.
- 바깥쪽에 정의된 메소드에서 처리하고자 하는 경우, `throw`문을 사용하여 **rethrow**하면 된다.
- **중첩**하여 `try-catch` 문을 사용할 수 있다.

```java
catch (ArithmeticException e)
{
    throw (e);   // 예외 e를 다시 발생
}
```

→ 다시 던지기와 중첩 `try-catch` 확인: [`examples/RethrowTest.java`](../examples/RethrowTest.java)

```
---- 다시 던지기 ----
calculate 에서 일부 처리 : / by zero
main 에서 최종 처리 : java.lang.ArithmeticException: / by zero
---- 중첩 try-catch ----
안쪽 try-catch : 배열 인덱스 오류
바깥 try 계속 실행
바깥 try-catch : 0 으로 나누기
```

> 💡 다시 던지는 이유: 예외가 난 곳에서 할 수 있는 일(기록 남기기, 일부 정리)만 하고, 최종 판단은 호출한 쪽에 맡기기 위해서다. `throw (e);`의 괄호는 없어도 된다.

### [실습] 다중 catch 문 – ArithmeticException

```java
class MultipleCatchTest {
    public static void main(String args[]) {
        try {
            int arr[] = new int[5];
            arr[4] = 20 / 0;   // 예외발생
            System.out.println("First print statement in try block");
        }
        catch (ArithmeticException e) {   // 여기서 받음
            System.out.println("Warning: ArithmeticException");
        }
        catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("Warning: ArrayIndexOutOfBoundsException");
        }
        catch (Exception e) {
            System.out.println("Warning: Some Other exception");
        }
        System.out.println("try-catch 블락 밖...");
    }
}
```

```
Warning: ArithmeticException
try-catch 블락 밖...
```

### [실습] 다중 catch 문 – ArrayIndexOutOfBoundsException

```java
class MultipleCatchTest {
    public static void main(String args[]) {
        try {
            int arr[] = new int[5];
            arr[6] = 20 / 5;   // 예외발생
            System.out.println("First print statement in try block");
        }
        catch (ArithmeticException e) {
            System.out.println("Warning: ArithmeticException");
        }
        catch (ArrayIndexOutOfBoundsException e) {   // 여기서 받음
            System.out.println("Warning: ArrayIndexOutOfBoundsException");
        }
        catch (Exception e) {
            System.out.println("Warning: Some Other exception");
        }
        System.out.println("try-catch 블락 밖...");
    }
}
```

```
Warning: ArrayIndexOutOfBoundsException
try-catch 블락 밖...
```

→ 두 경우를 한 파일로: [`examples/MultipleCatchTest.java`](../examples/MultipleCatchTest.java)

> 💡 **보충:**
> - 처음으로 타입이 맞는 `catch` **하나만** 실행되고 나머지는 건너뛴다.
> - `arr[4] = 20/0;`처럼 대입문은 **오른쪽 식을 먼저** 계산한다. 그래서 첫 번째 경우에는 인덱스와 상관없이 나눗셈 예외가 먼저 난다. 두 번째 경우는 `20 / 5 = 4`는 문제없고, 인덱스 6에 저장하다가 예외가 난다.
> - 두 경우 모두 예외가 난 다음 줄인 `"First print statement in try block"`은 출력되지 않는다.

> ⚠ **자주 틀리는 부분 (퀴즈 4번):** `catch (Exception e)`를 맨 위에 두면 아래 `catch`는 절대 실행될 수 없어서 **컴파일 오류**가 난다.
> ```
> error: exception ArithmeticException has already been caught
> ```
> `Exception`은 모든 예외의 부모라서, 위에 있으면 자식 예외까지 다 잡아 버린다. **구체적인 하위(자식) 예외를 위에, 포괄적인 상위(부모) 예외를 아래에** 쓴다. `Exception`은 "위에서 미처 잡지 못한 나머지 모든 예외"를 처리하는 용도로 맨 마지막에 둔다.
> ```java
> try { .... }
> catch (IOException e) { ... }   // 1. 하위(자식) 예외 클래스를 먼저 배치
> catch (Exception e)   { ... }   // 2. 상위(부모) 예외 클래스를 나중에 배치
> ```

## 4. 📝 예외 클래스의 계층 구조 (퀴즈 1번)

> 📝 **필기:** `throw`로 던질 수 있는 유형이 Java에서는 **`Throwable` 타입만** 가능하도록 한정되어 있다. `Throwable`은 클래스로, 이를 상속받아 만들어진 `Error`, `Exception` 객체도 가능하다.
> - 프로그래머가 조치를 취할 수 있는 경우의 에러가 아닌 하드웨어 등 → **`Error`**
> - 소프트웨어적으로 조치를 취할 수 있는 경우 → **`Exception`**
> - `Exception` 밑에는 또 **`RuntimeException`**이 있다.

```
        Object
          ↑
      Throwable
       ↗      ↖
   Error     Exception
                ↑
         RuntimeException
```

| 클래스 | 설명 |
|---|---|
| `Throwable` | Java에서 예외 처리를 할 수 있는 최상위 클래스. 오직 `Throwable`과 그 자식 클래스의 객체만 `throw`로 던질 수 있고, `catch` 블록의 매개변수로 선언될 수 있다. |
| `Error` | 하드웨어의 고장, JVM의 리소스 부족(`OutOfMemoryError`, `StackOverflowError`) 등 시스템 레벨의 심각한 문제. 코드로는 조치·복구할 수 없어서 `try-catch`로 잡으려고 하지 않는다. |
| `Exception` | 프로그램 실행 중 발생할 수 있는 비교적 경미한 오류. 파일이 없거나 네트워크가 끊기는 등의 상황에서 `try-catch`로 비정상 종료를 막고 정상 흐름을 유지할 수 있다. |
| `RuntimeException` | `Exception`의 하위 클래스. 주로 프로그래머의 실수로 발생한다(`ArrayIndexOutOfBoundsException`, `NullPointerException`, `ArithmeticException`). 컴파일러가 예외 처리를 강제하지 않는다(11-2 unchecked). |

> ⚠ **자주 틀리는 부분 (퀴즈 1번):** `throw "하드디스크가 가득 찼습니다.";`와 `catch (String s)`는 컴파일 오류다. `String`은 `Throwable`을 상속하지 않았기 때문이다(`error: incompatible types: String cannot be converted to Throwable`). C++은 아무 타입이나 던질 수 있어서 헷갈리기 쉽다. 자바에서는 `throw new Exception("하드디스크가 가득 찼습니다.");`처럼 예외 **객체**를 만들어 던진다.
