## 1. 자바의 역사

| 연도 | 내용 |
|---|---|
| 1991 | 썬 마이크로시스템즈에서 개발 시작 |
| 1995 | **자바 1.0** 발표. C++와 문법·구조가 비슷하다. "한 번 작성하면 여러 OS에서 실행"을 목표로 했다 |
| 2010 | 썬이 **오라클**에 합병되어 소유권이 이전됨 |
| 2025 | 자바 25 |
| 2026 | 자바 26 |

- 버전 표기는 두 가지다.
  - **Java 6** 같은 짧은 형식은 "제품 버전"이다.
  - **Java 1.6.0** 같은 긴 형식은 "개발자 버전"이다.

## 2. 자바의 특성

| 특성 | 설명 |
|---|---|
| **플랫폼 독립적** | JVM(Java Virtual Machine) 위에서 실행되므로 OS에 직접 접근할 필요가 없다. JVM만 설치되어 있으면 HW나 OS와 상관없이 실행된다 (이식성이 높다) |
| **객체지향 언어** | 클래스와 객체로 프로그램을 구성한다 |
| **컴파일 + 인터프리트** | 소스를 바이트코드로 **컴파일**한 뒤 JVM이 **인터프리트**한다. 인터프리트가 느린 점은 **JIT 컴파일**로 보완한다. JIT은 한 번 번역한 기계어 코드를 보관해, 같은 함수를 여러 번 부를 때 매번 다시 번역하지 않게 한다 |
| **자동 메모리 관리** | 객체를 만드는 시점은 프로그래머가 정한다. 쓰지 않는 객체는 **가비지 컬렉터(garbage collector)** 가 자동으로 수거한다. C/C++처럼 직접 해제하지 않는다 |
| **높은 보안성** | JVM 안에서 실행되므로 코드를 안전하게 관리할 수 있다. HW에서 직접 실행되는 C/C++보다 보안성이 높다 |

## 3. 객체지향 프로그래밍(OOP)이란?

- 객체는 **필드(Field, Attribute)** 와 **메소드(Method)** 로 구성된다.
  - 필드는 객체가 내부에 가진 데이터다.
  - 메소드는 객체의 고유 기능이다.
- 필드에는 메소드를 통해 접근한다.
- 프로그램은 객체의 작은 기능들을 조합해 복잡한 기능을 만든다.

```
  자동차 객체 ①            자동차 객체 ②            자동차 객체 ③
  ┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
  │ color : green    │    │ color : blue     │    │ color : red      │  ← 필드 (데이터는 다름)
  │ speed : 30       │    │ speed : 40       │    │ speed : 20       │
  ├──────────────────┤    ├──────────────────┤    ├──────────────────┤
  │ stop() start()   │    │ stop() start()   │    │ stop() start()   │  ← 메소드 (기능은 같음)
  │ speedUp()        │    │ speedUp()        │    │ speedUp()        │
  │ speedDown()      │    │ speedDown()      │    │ speedDown()      │
  └──────────────────┘    └──────────────────┘    └──────────────────┘
```

- **클래스**는 데이터 유형과 메소드로 이루어진 틀(**붕어빵 틀**)이다.
- **객체**는 그 틀로 찍어낸 것(**붕어빵**)이다.
- 같은 클래스로 만든 객체는 데이터 유형과 메소드가 같다. 담긴 데이터는 다르다.
- OOP는 개발과 유지보수를 쉽게 하고 재사용성을 높인다. 그래서 대규모 개발에 많이 쓴다.

| 주요 특징 | 의미 |
|---|---|
| **캡슐화** | 외부에서 데이터에 직접 접근하지 못하게 하고 메소드를 통해서만 접근하게 해 부작용을 막는다 |
| **상속** | 기존 클래스를 물려받아 기능을 추가하거나 바꾼 새 클래스를 만든다 |
| **다형성** | 하나의 코드로 여러 유형의 데이터를 처리한다 |

## 4. 왜 자바를 배워야 하나?

- **인기가 높다.** 아래 지표에서 꾸준히 상위권이다.
  - TIOBE 인덱스: 검색량 기반, 누적 관심도
  - PYPL 인덱스: 튜토리얼 검색량 기반, 현재 관심도
  - Stack Overflow Developer Survey 2025: 현업 사용성
- **취업 기회가 많다.**
  - 금융, 통신, 전자상거래 등 엔터프라이즈 대규모 시스템에 오래 쓰여 왔다.
  - 국내에서는 정부 기관과 대기업 시스템 대부분이 자바로 만들어져 있다.
- **생태계와 안정성이 강하다.**
  - 라이브러리와 프레임워크가 방대하다. 대표적으로 **Spring**이 있다.
  - 오랜 기간 안정성과 보안성이 검증되었다.
- **Write Once, Run Anywhere.**
  - JVM 덕분에 윈도우, 리눅스, macOS에서 코드를 수정하지 않고 실행할 수 있다.
- **OOP를 배우기 좋다.**
  - 상속, 다형성, 캡슐화를 자연스럽게 익힐 수 있다.
  - 이 개념은 다른 언어를 배울 때도 기반이 된다.

## 5. 자바 개발 환경

### 자바 플랫폼

**구성 요소**
- 자바 언어
- 컴파일러
- JVM
- 가비지 컬렉터
- API (클래스 라이브러리)

**종류**

| 플랫폼 | 용도 |
|---|---|
| **Java SE** | 가장 널리 쓰이는 표준 자바 API |
| Java EE | SE에 대규모·다층 구조 응용 프로그램용 API를 더한 것 |
| Java ME | 휴대전화, 셋톱박스 등 자원이 제한된 기기용 |
| Java FX | RIA(Rich Internet Application)용 |

### JDK와 JRE

- **JDK (Java Development Kit)**
  - 자바 플랫폼의 구현체다.
  - 컴파일러, 각종 도구, JRE, 클래스 라이브러리를 포함한다.
- **JRE (Java Runtime Environment)**
  - JVM과, 실행에 필요한 클래스 라이브러리를 포함한다.
  - 자바 9부터 JRE 폴더가 따로 없고 JDK에 통합되었다.
  - 실행 파일은 `bin`, 라이브러리는 `lib`에 있다.

```
JDK ⊃ JRE ⊃ JVM
```

**JDK `bin` 폴더의 주요 도구**

| 도구 | 역할 |
|---|---|
| `javac` | 자바 소스코드를 **바이트코드(.class)** 로 바꾸는 컴파일러 |
| `java` | 자바 응용프로그램 실행기. JVM을 띄워 프로그램을 실행한다 |
| `javadoc` | 소스 주석으로 HTML API 문서를 만든다 |
| `jar` | 자바 아카이브(JAR) 파일을 만들고 관리한다 |
| `jdb` | 디버거 |
| `javap` | `.class` 파일을 역어셈블해서 보여준다 |

## 6. JDK 설치

1. https://www.oracle.com/java/ 에서 JDK를 내려받아 설치한다.
2. 환경변수를 설정한다.
   - 내 PC → 속성 → 고급 시스템 설정 → 환경 변수로 들어간다.
   - 시스템 변수 **Path**를 선택하고 편집 → 새로 만들기를 누른다.
   - JDK의 `bin` 폴더를 추가한다. 예: `C:\Program Files\Java\jdk-25.0.4\bin`
3. cmd에서 확인한다.
   ```bash
   java -version   # 설치된 자바 버전 출력
   javac           # 컴파일러 사용법이 출력되면 OK
   ```
   두 명령이 모두 제대로 실행되면 설치 성공이다.

## 7. 자바 개발 과정 (명령 프롬프트)

```
HelloWorld.java  ──javac──▶  HelloWorld.class  ──java──▶  JVM 에서 실행
  (소스코드)       컴파일        (바이트코드)       실행
```

```bash
javac HelloWorld.java   # 컴파일 → 같은 폴더에 HelloWorld.class 생성
java HelloWorld         # 실행 (.java / .class 확장자를 붙이지 않는다!)
```

- `.class` 파일이 생기지 않았다면 컴파일 오류가 난 것이다. 오타가 없는지 확인한다.
- `javac`가 동작하지 않는다면 **Path 설정**을 확인한다.

## 8. 이클립스 (Eclipse)

- 메모장으로도 자바 프로그램을 작성할 수 있다.
- 보통은 **IDE**(통합 개발 환경)를 쓰며, 대표적인 것이 이클립스다.
- 설치: https://www.eclipse.org/downloads/ → **Eclipse IDE for Java Developers**

**프로젝트 만들기와 실행**
1. **File → New → Java Project**를 선택한다. Package Explorer의 *Create a Java project*를 눌러도 된다.
2. 프로젝트 이름을 입력하고 **Finish**를 누른다.
3. `src`에서 우클릭 → **New → Class**를 선택한다. 클래스 이름을 입력하고 `public static void main` 옵션을 체크한다.
4. 초록색 **Run** 아이콘(**Ctrl + F11**)을 눌러 실행한다. 오류가 있으면 콘솔 뷰에 메시지가 나온다.

## 9. 이클립스 한글 깨짐 해결

원인은 프로젝트, 워크스페이스, 실행 환경의 **인코딩이 서로 다르기** 때문이다. 모두 **UTF-8**로 통일하면 해결된다.

| 대상 | 설정 위치 |
|---|---|
| ① 워크스페이스 (새 프로젝트 기본값) | Window → Preferences → General → Workspace → Text file encoding → Other: **UTF-8** |
| ② 프로젝트별 (기존·외부 프로젝트) | 프로젝트 우클릭 → Properties → Resource → Text file encoding → Other: **UTF-8** |
| ③ 콘솔 출력 | Run → Run Configurations → 실행 중인 클래스 선택 → Common 탭 → Encoding → Other: **UTF-8** |

**그래도 안 될 경우**
- **파일 인코딩 변경:** 파일 우클릭 → Properties → Resource → Text file encoding을 **UTF-8**로 바꾸고 이클립스를 재시작한다.
  그래도 깨져 있으면 코드를 새 UTF-8 파일에 붙여 넣는다.
- **VM 인수 추가:** Run Configurations → Arguments 탭 → VM arguments에 아래를 넣고 실행한다.
  ```
  -Dfile.encoding=UTF-8
  ```
